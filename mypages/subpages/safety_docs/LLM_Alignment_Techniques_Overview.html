1. 对齐技术概述

1.1 对齐问题的起源

大型语言模型（LLM）建立在海量无监督语料的自回归预训练之上，其本质是对互联网文本中下一个Token的极大似然预测——这是一个统计目标，而非"有用、无害、诚实"的对齐目标。预训练模型在诸多语言任务上表现出惊人能力，但这种能力并不等价于与人类意图的真正对齐。

对齐（Alignment） 的目标是让模型行为符合人类价值观、意图和偏好，解决"能力-意图鸿沟"。

2. RLHF：基于人类反馈的强化学习

2.1 核心原理

RLHF（Reinforcement Learning from Human Feedback）通过人类反馈来训练奖励模型，再通过强化学习指导语言模型行为的优化。这是当前最成熟、最广泛验证的对齐技术。

2.2 三阶段训练流程

┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  阶段1: SFT     │ → │  阶段2: RM训练   │ → │  阶段3: RL优化   │
│  监督微调        │    │  奖励模型训练     │    │  策略优化        │
└─────────────────┘    └─────────────────┘    └─────────────────┘

阶段1：监督微调（SFT）

  • 在高质量人工编写的演示数据上进行初始微调

  • 建立模型的基准行为，使其学会遵循指令的基本格式

  • 数据质量直接决定后续对齐的上限

阶段2：奖励模型训练（RM）

  • 人类标注员对同一Prompt的多个模型输出进行排序（偏好排序）

  • 基于这些排序数据训练奖励模型，使其能够预测人类偏好

  • 奖励模型输出标量分数，代表"人类会多喜欢这个回答"

阶段3：强化学习优化（PPO）

  • 使用近端策略优化（PPO）算法优化语言模型

  • 目标：最大化奖励模型的分数，同时保持合理的输出多样性

  • 通过KL散度正则化防止策略偏离参考模型太远

2.3 核心算法：PPO

PPO（Proximal Policy Optimization）是 RLHF 阶段3的核心算法，通过裁剪目标函数防止策略更新过大：

​x
L^CLIP(θ) = E_t [ min(r_t(θ) * A_t, clip(r_t(θ), 1-ε, 1+ε) * A_t) ]


其中:
- r_t(θ) = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)  策略比率
- A_t  优势函数估计
- ε  裁剪超参数（通常0.1-0.2）

2.6 实践建议

  • 数据集至少需要 2000条以上 偏好数据才有效果

  • 奖励模型（RM）越大，策略模型能在不偏离的情况下走得更远

  • 策略模型越大，从RM获得的相对收益越小（边际递减）

  • 使用KL散度等指标跟踪训练过程，避免过度优化

3. RLAIF：基于AI反馈的强化学习

3.1 核心原理

RLAIF（Reinforcement Learning from AI Feedback）用强大的AI模型（教师模型）替代人类标注员，给模型的输出打分、纠错、优化。这是2026年主流大模型普遍采用的对齐技术。

3.5 关键注意事项

  • 教师模型容量要求：训练70B模型时，AI反馈应来自1T+参数的旗舰模型。教师模型至少比目标模型大一个数量级，才能提供有效反馈

  • 种子数据校准：仍需少量人类标注的种子数据集用于校准AI评判标准

  • 持续审计：需要人类审计和抽查，分析AI与人类判断的分歧

  • 单模型生成偏好：安全关键应用中，使用单一模型生成偏好对的chosen和rejected响应，避免多模型比较引入分布不一致

4. Constitutional AI：宪法AI

4.1 核心原理

Constitutional AI（CAI）由 Anthropic 提出，是一种特殊的 RLAIF 方法。它不依赖人类标注有害输出，而是让模型根据一套预设的"宪法原则"（Constitution）进行自我监督和自我修正。

核心理念：用明确的、可审计的自然语言规则约束模型行为，实现"helpful, harmless, and honest by design"。

5. DPO：直接偏好优化

5.1 核心原理

DPO（Direct Preference Optimization）由 Rafailov 等人于2023年提出，是RLHF的简化版。其核心洞见是：RLHF的优化目标可以推导成一个等价的监督学习损失，绕过显式奖励模型，直接用（提示，好回答，差回答）三元组训练。

5.2 数学推导

DPO 直接从偏好数据推导最优策略，无需训练单独的奖励模型：

xxxxxxxxxx
# 简化的DPO损失函数
def dpo_loss(policy_logps_chosen, policy_logps_rejected,
             ref_logps_chosen, ref_logps_rejected, beta=0.1):
    chosen_rewards = beta * (policy_logps_chosen - ref_logps_chosen)
    rejected_rewards = beta * (policy_logps_rejected - ref_logps_rejected)
    loss = -F.logsigmoid(chosen_rewards - rejected_rewards)
    return loss.mean()

关键参数：

  • beta：温度参数，控制策略与参考模型的偏离程度

  • policy_logps：策略模型（待优化模型）的对数概率

  • ref_logps：参考模型（通常是SFT后的模型）的对数概率

5.3 DPO 与传统 RLHF 对比

5.4 DPO 的优势

  • 简单高效：无需训练奖励模型，直接优化偏好目标

  • 训练稳定：避免了PPO的复杂调参和不稳定性

  • 资源友好：显存需求显著降低，适合中小团队

  • 效果接近：在多个基准上与RLHF效果相当甚至更优

5.5 DPO 的局限

  • 过拟合风险：在小偏好数据集上容易过拟合，尤其当参考模型概率不再有意义时

  • 探索能力弱：不如精心调优的RLHF具有探索能力

  • 分布偏移敏感：对新偏好数据的需求高，对分布偏移敏感

  • 效果上限：最终效果受限于偏好数据的质量和覆盖范围

7. 新兴对齐范式

7.1 GRPO：组相对策略优化

GRPO（Group Relative Policy Optimization）是 DeepSeek 在2024年提出的PPO改进版，2026年成为最热的对齐方案：

核心改进：砍掉PPO的Value Model，改用"同一问题采样G个回答、用组内相对排名作为基线"估计优势函数。

优势：

  • 省掉Value Model的训练成本

  • 显存减半

  • DeepSeek R1、DeepSeek-Math、Qwen系列推理模型均采用

7.2 RLVR：可验证奖励强化学习

RLVR（Reinforcement Learning from Verifiable Rewards）是2026年推理模型（如o1）采用的新范式：

核心差异：

  • RLHF/RLAIF 关注偏好对齐（风格、语气、安全）

  • RLVR 提供客观真值反馈（如"代码是否运行？"、"数学是否正确？"）

适用场景：逻辑推理、代码生成、数学证明等可验证任务。

7.3 拒绝采样微调（Rejection Sampling Fine-tuning）

流程：生成 → 筛选 → 再SFT循环

  • 让模型对每个Prompt生成多个回答

  • 用奖励模型筛选高分回答

  • 对筛选后的数据进行一轮SFT

特点：流程上没有RL，简单粗暴但有效。Llama 2的对齐流程中使用了此方法。

7.4 自奖励语言模型（Self-Rewarding LM）

模型自身充当奖励模型，通过迭代自我改进实现对齐。减少对外部反馈的依赖，是"自对齐"技术的前沿方向。

8.5 关键成功因素

  1. 数据质量优先：对齐效果的上限由数据质量决定，而非算法复杂度

  2. 持续监控：使用KL散度、奖励模型分数、人类评估等多维度跟踪

  3. 避免奖励黑客：奖励分数上升不等于真实性能提升，需独立评估

  4. 多维度评估：不仅评估有用性，还需评估安全性、诚实性、事实性

  5. 迭代优化：对齐不是一次性任务，需要持续收集反馈、迭代改进
