RLHF 人类反馈机制详解

一、概述

Reinforcement Learning from Human Feedback（RLHF，人类反馈强化学习）是大语言模型后训练阶段的核心技术，用于将模型输出与人类偏好对齐。RLHF 使模型从"能回答问题"进化到"给出人类真正想要的回答"——更 helpful（有帮助）、harmless（无害）、honest（诚实）。

1.1 为什么需要 RLHF

预训练模型通过海量文本学习了语言模式，但缺乏对"什么是好回答"的判断能力：

  • 可能生成语法正确但内容有害的回答

  • 可能给出冗长、啰嗦但信息量低的回答

  • 可能在多轮对话中偏离用户意图

  • 可能无法拒绝危险请求或表达不确定性

RLHF 通过引入人类价值判断，将主观偏好转化为可优化的训练信号，使模型学会在多种合理回答中选择更符合人类期望的那一个。

1.2 RLHF 的核心流程

预训练模型
    ├──→ 阶段一：SFT（监督微调）
    │      └── 学习指令遵循格式
    │
    ├──→ 阶段二：奖励模型训练
    │      └── 学习人类偏好评分
    │
    └──→ 阶段三：RL 优化（PPO）
           └── 最大化奖励 + KL 约束

2.2 偏好对格式

标准偏好数据包含：提示（Prompt）、被选回答（Chosen）、被拒绝回答（Rejected）：

xxxxxxxxxx
{
  "prompt": "请解释量子纠缠的概念。",

  "rejected": "量子纠缠就是两个粒子连在一起的意思。"

2.3 标注维度

人类标注通常从多个维度评估：

  • Helpfulness（有帮助性）：回答是否真正解决了用户问题

  • Harmlessness（无害性）：回答是否包含有害、偏见或危险内容

  • Honesty（诚实性）：回答是否基于事实，是否承认不确定性

  • Coherence（连贯性）：回答是否逻辑清晰、结构合理

  • Conciseness（简洁性）：回答是否简洁而不冗余

三、奖励模型（Reward Model）

3.1 核心思想

奖励模型是一个标量评分函数，输入为（提示，回答），输出为一个实数值，表示该回答在人类偏好上的得分高低。奖励模型将人类的主观偏好转化为模型可优化的客观信号。

3.2 Bradley-Terry 偏好模型

奖励模型的训练基于 Bradley-Terry 模型，假设人类偏好的概率与奖励差值的 sigmoid 成正比：

xxxxxxxxxx
P(y_w > y_l | x) = σ(r(x, y_w) - r(x, y_l))

其中：

  • x：提示（Prompt）

  • y_w：被选中的（更优的）回答

  • y_l：被拒绝的（较差的）回答

  • r(x, y)：奖励模型对回答 y 的评分

  • σ：sigmoid 函数

3.3 奖励模型训练

3.3.1 模型架构

奖励模型通常从 SFT 模型初始化，将最后一层替换为标量输出头：

xxxxxxxxxx
输入 Token → Transformer 编码 → 最后一层隐藏状态 → 线性层 → 标量奖励值

对于生成序列，奖励值通常取最后一个 token 的隐藏状态或所有 token 隐藏状态的平均值。

3.3.2 损失函数

xxxxxxxxxx
L_RM = -E[(x, y_w, y_l) ~ D] [log σ(r(x, y_w) - r(x, y_l))]

即最大化"被选回答的奖励高于被拒绝回答的奖励"这一事件的对数概率。

3.3.3 训练要点

  • 数据质量：奖励模型的数据质量通常低于 SFT 数据，因此 RLHF 通常在 SFT 之后进行

  • 模型规模：奖励模型需要足够大以捕捉细微的质量差异，通常与策略模型同规模或略小

  • 正则化：防止奖励模型过拟合到特定标注者的偏好

  • 校准：确保奖励分数在不同提示间具有可比性

3.4 奖励模型的局限

  • 奖励黑客（Reward Hacking）：模型可能发现奖励模型的漏洞，生成高分但低质量的回答（如过度冗长）

  • 分布外泛化：奖励模型在训练分布外的提示上可能给出不可靠的评分

  • 标注者间差异：不同标注者的偏好可能冲突，导致奖励信号不一致

  • 稀疏性：句子级别的奖励信号难以指导 token 级别的生成决策

四、PPO（Proximal Policy Optimization）算法

4.1 核心思想

PPO 是 RLHF 第三阶段的核心算法，用于在奖励模型的指导下优化语言模型策略。PPO 通过裁剪目标函数限制每次策略更新的幅度，防止策略发生剧烈变化导致训练不稳定。

4.2 训练架构

PPO 训练需要同时运行四个模型：

4.3 PPO 目标函数

4.3.1 裁剪替代目标

xxxxxxxxxx
L_CLIP(θ) = E_t [min(r_t(θ) * A_t, clip(r_t(θ), 1-ε, 1+ε) * A_t)]

其中：

  • r_t(θ) = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)：新旧策略的概率比

  • A_t：优势函数（Advantage），衡量当前动作相对于平均水平的优劣

  • ε：裁剪系数（通常 0.1~0.2），限制策略更新幅度

4.3.2 完整 PPO 损失

xxxxxxxxxx
L_PPO = L_CLIP - c1 * L_VF + c2 * S[π_θ] + β * KL(π_θ || π_ref)

各项含义：

  • L_CLIP：裁剪替代目标，最大化优势

  • L_VF：价值函数损失，Critic 预测准确性

  • S[π_θ]：策略熵，鼓励探索

  • KL(π_θ || π_ref)：KL 散度惩罚，防止策略偏离参考模型太远

4.4 优势估计（GAE）

Generalized Advantage Estimation（GAE）用于计算优势函数：

xxxxxxxxxx
A_t^GAE(γ, λ) = Σ (γλ)^l * δ_{t+l}

其中 δ_t = r_t + γV(s_{t+1}) - V(s_t) 是 TD 残差。GAE 在偏差和方差之间做权衡，λ=1 时无偏差但方差大，λ=0 时偏差大但方差小。

4.5 PPO 训练流程

xxxxxxxxxx
1. 初始化：Actor = SFT 模型，Critic = SFT 模型副本，Reward Model = 预训练 RM，Reference = 冻结 SFT
2. 采样阶段：
   - Actor 生成一批回答
   - Reward Model 为每个回答打分
   - Critic 估计每个 token 的价值
   - 计算 KL 惩罚后的最终奖励
3. 优化阶段：
   - 计算优势函数（GAE）
   - 更新 Actor（最大化裁剪目标）
   - 更新 Critic（最小化价值损失）
4. 重复步骤 2-3 直到收敛

4.6 PPO 的挑战

  • 训练不稳定：超参数敏感，学习率、KL 系数、裁剪系数需精细调优

  • 内存开销大：四个模型同时驻留 GPU，内存需求约为 SFT 的 4 倍

  • 奖励黑客：模型可能利用奖励模型的弱点（如生成冗长回答获取高分）

  • 计算成本高：每步需要在线采样生成回答，推理开销大

  • 调试困难：多个组件交互，问题定位复杂

五、DPO（Direct Preference Optimization）

5.1 核心思想

DPO 是 2023 年由 Stanford 提出的 RLHF 简化方案。其核心洞察是：不需要显式训练奖励模型，也不需要运行 RL 循环。通过数学推导，可以将奖励函数与最优策略建立解析映射，直接将偏好优化转化为分类损失。

5.2 理论推导

5.2.1 从奖励到策略的映射

在 RL 框架下，最优策略与奖励函数的关系为：

xxxxxxxxxx
π*(y|x) = (1/Z(x)) * π_ref(y|x) * exp(r(x,y)/β)

其中：

  • π*：最优策略

  • π_ref：参考策略（SFT 模型）

  • r(x,y)：奖励函数

  • β：温度参数，控制与参考模型的偏离程度

  • Z(x)：配分函数（归一化常数）

5.2.2 从策略反推奖励

对上述公式取对数并整理，可得：

xxxxxxxxxx
r(x,y) = β * log(π*(y|x) / π_ref(y|x)) + β * log(Z(x))

将这一隐式奖励代入 Bradley-Terry 模型，消去配分函数 Z(x)，得到 DPO 损失：

5.3 DPO 损失函数

xxxxxxxxxx
L_DPO = -E[(x, y_w, y_l) ~ D] [log σ(β * log(π_θ(y_w|x) / π_ref(y_w|x)) - β * log(π_θ(y_l|x) / π_ref(y_l|x)))]

简化形式：

xxxxxxxxxx
L_DPO = -log σ(β * (log π_θ(y_w|x) - log π_ref(y_w|x) - log π_θ(y_l|x) + log π_ref(y_l|x)))

直观理解：

  • 最大化"被选回答相对于参考模型的对数概率提升"

  • 最小化"被拒绝回答相对于参考模型的对数概率提升"

  • 两者之差通过 sigmoid 转化为分类损失

5.4 DPO 与 RLHF 的对比

5.5 DPO 的优势

  • 简化流程：无需训练单独的奖励模型，无需 RL 循环

  • 训练稳定：转化为分类损失，训练动态类似监督学习

  • 内存友好：仅需策略模型和参考模型

  • 实现简单：核心逻辑仅需几十行代码

  • 效果可比：在多数基准上达到或超越 PPO 效果

5.6 DPO 的局限

  • 离线方法：训练数据固定，无法像 PPO 那样在线探索

  • 过拟合风险：在小数据集上容易过拟合到偏好对

  • 分布偏移：训练分布与评估分布不一致时性能下降

  • 参考模型依赖：假设参考模型的概率有意义，大幅偏离后可能失效

  • 长度偏差：倾向于生成更长的回答（可通过 R-DPO 等变体缓解）

六、DPO 变体与进阶方法

6.1 IPO（Identity Preference Optimization）

IPO 修正了 DPO 在噪声偏好数据上的偏差：

  • DPO 假设偏好数据完全符合 Bradley-Terry 模型

  • IPO 引入身份映射约束，对高噪声数据集更鲁棒

  • 适用场景：标注质量参差不齐、存在大量模糊偏好的数据集

6.2 KTO（Kahneman-Tversky Optimization）

KTO 使用二元信号而非成对偏好：

  • 只需"好/坏"标签，无需成对比较

  • 基于前景理论（Prospect Theory）建模人类决策偏差

  • 适用场景：只有单点反馈（如点赞/点踩）而无法生成对比对的场景

6.3 SimPO（Simple Preference Optimization）

SimPO 进一步简化 DPO：

  • 移除参考模型的 KL 约束项

  • 直接使用策略模型的概率比作为训练信号

  • 适用场景：计算资源极度受限、单 GPU 微调小模型（≤7B）

6.4 R-DPO（Length-Controlled DPO）

R-DPO 解决 DPO 的长度偏差问题：

  • 在损失函数中显式引入长度惩罚项

  • 防止模型通过增加回答长度获取更高奖励

  • 适用场景：对回答长度有严格要求的场景

6.5 ORPO（Odds Ratio Preference Optimization）

ORPO 将 SFT 和偏好优化合并为单阶段：

  • 不需要参考模型

  • 在标准语言建模损失中融入偏好信号

  • 适用场景：单 GPU、小模型、极简部署

6.6 RTO（Reinforced Token Optimization）

RTO 是 DPO 与 PPO 的融合方案：

  • 使用 DPO 推导 token 级别的奖励信号

  • 然后使用 PPO 进行策略优化

  • 兼具 DPO 的细粒度信号和 PPO 的在线探索能力

  • 在 AlpacaEval 2 上比 PPO 提升 7.5 分

八、RLHF 实践要点

8.2 训练稳定性技巧

PPO：

  • 使用梯度累积模拟大 batch

  • 监控 KL 散度，超过阈值时暂停更新

  • 价值函数使用独立的学习率

  • 对奖励进行归一化（z-score）

DPO：

  • 通常 1 个 epoch 即可，避免过拟合

  • 使用 bf16 混合精度训练

  • 配合 LoRA/QLoRA 降低内存占用

  • 监控被选/被拒绝回答的概率比

8.3 评估指标

  • Win Rate：模型 A 的回答被评委模型/人类判定优于模型 B 的比例

  • Elo Score：基于成对比较的等级评分

  • Length-Controlled Win Rate (LC)：控制回答长度后的胜率，消除长度偏差

  • MT-Bench：多轮对话能力评分

  • AlpacaEval：指令遵循能力评估

  • Safety Score：有害内容检测通过率

九、RLHF 的局限与前沿方向

9.1 当前局限

  • 标注成本高：高质量人类偏好数据昂贵且难以规模化

  • 标注者间差异：不同文化、背景的标注者偏好可能冲突

  • 奖励模型偏差：奖励模型可能继承并放大训练数据中的偏见

  • 分布外脆弱：在训练分布外的任务上可能表现不佳

  • 对齐税：过度对齐可能导致模型能力退化（如创造性下降）

9.2 前沿方向

  • RLAIF（AI Feedback）：使用强 LLM 替代人类标注，大幅降低成本

  • Constitutional AI：AI 根据预设原则自我批判和修正，减少对人类标注的依赖

  • Online DPO：在 DPO 中引入在线采样，兼具 DPO 的简洁和 PPO 的探索能力

  • 多目标对齐：同时优化 helpfulness、harmlessness、honesty 等多个维度

  • 可解释对齐：使对齐过程可解释、可审计、可撤销

十、总结

RLHF 的本质是将人类主观价值判断转化为可优化的数学目标。从最初的三阶段 PPO pipeline 到如今的 DPO 及其变体，这一领域正在从"复杂但强大"向"简单且有效"演进。对于绝大多数实践者，DPO 已成为 2026 年的默认选择——它以更少的工程复杂度实现了相当甚至更优的对齐效果。而对于追求极致性能的前沿实验室，PPO 与 DPO 的混合方案（如 RTO）以及 RLAIF 等自动化反馈机制，正在重新定义对齐技术的边界。
