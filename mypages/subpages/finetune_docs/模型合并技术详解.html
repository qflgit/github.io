模型合并技术详解

一、概述

模型合并（Model Merging）是一种无需额外训练即可将多个模型的能力整合到单一模型中的技术。其核心思想是在权重空间而非数据空间进行操作，通过数学方法将多个模型的参数融合为一个新模型。这种方法具有零训练成本、可组合性强、可解释性高等优势，已成为大语言模型领域的重要研究方向。

1.1 为什么模型合并有效

模型合并之所以有效，基于两个关键假设：

  • 模态连通性（Mode Connectivity）：从同一预训练模型微调而来的多个模型，其权重仍位于损失景观的同一低损失区域内。对这些权重进行插值或平均，结果通常仍落在低损失区域。

  • 任务向量的正交性：不同任务微调产生的参数更新（任务向量）在权重空间中近似正交，因此叠加时不会相互抵消。

1.2 适用前提

  • 所有待合并模型必须共享相同的架构

  • 最佳效果出现在模型源自同一预训练基座时

  • 模型合并发生在离线阶段，无需 GPU 训练

二、基础方法

2.1 线性插值（Linear Interpolation）

最简单直接的合并方法，对两个模型的权重进行逐元素加权平均：

W_merged = α × W_A + (1 - α) × W_B

当 α = 0.5 时，两个模型贡献相等。该方法适用于从同一基座微调、目标相近的模型。但当微调方向冲突时，线性平均会产生灾难性干扰（Catastrophic Interference），导致合并模型在两个任务上的表现都不如任一父模型。

2.2 模型汤（Model Soup）

模型汤是线性插值的扩展，对使用不同超参数训练得到的多个模型进行加权平均。与简单平均不同，模型汤通过贪心策略选择哪些模型纳入合并池，通常能在验证集上超越最佳单个模型。

三、SLERP（Spherical Linear Interpolation，球面线性插值）

3.1 核心思想

SLERP 将权重张量视为向量，在单位球面的测地线上进行插值，而非欧几里得空间的直线。这避免了线性插值在中间值处产生的权重范数收缩问题。

3.2 数学公式

xxxxxxxxxx
W_merged = sin((1-t) × θ) / sin(θ) × W_A + sin(t × θ) / sin(θ) × W_B

其中 θ 是两个归一化权重向量之间的夹角，t ∈ [0, 1] 为插值系数。

3.3 特点与适用场景

  • 保持范数：避免线性插值在中间值处的权重 shrinkage

  • 平滑过渡：在 t = 0.5 时保持更好的模型一致性

  • 最佳场景：合并两个来自同一模型家族的相似模型

  • 局限：仅适用于两模型合并，无法直接扩展到多模型场景

四、Task Arithmetic（任务算术）

4.1 核心思想

Task Arithmetic 将模型合并的视角从"绝对权重"转向"相对变化"，引入了任务向量（Task Vector）的概念。

4.2 任务向量定义

任务向量 τ 定义为微调模型与预训练基座模型之间的参数差：

xxxxxxxxxx
τ_i = θ_i^fine-tuned - θ^pretrained

任务向量编码了从预训练到特定任务的能力迁移信号。

4.3 合并公式

xxxxxxxxxx
θ_merged = θ^pretrained + Σ λ_i × τ_i

其中 λ_i 为各任务向量的缩放系数：

  • λ_i > 0：添加该任务的能力

  • λ_i < 0：移除/抑制该任务的能力（如去除有害行为）

  • |λ_i| 大小：控制该能力的强度

4.4 关键特性

  • 可组合性：任务向量可以像代数运算一样自由加减缩放

  • 可解释性：每个任务向量对应明确的能力维度

  • 正交性假设：不同任务的任务向量近似正交，叠加时互不干扰

  • 缩放系数调优：λ 需要针对具体场景调优，典型默认值：两模型合并取 0.4，三模型及以上取 0.3

4.5 局限

当合并模型数量增多或任务差异较大时，任务向量之间可能出现符号冲突（Sign Conflicts）——同一参数位置在不同任务向量中符号相反，简单平均会导致相互抵消，产生近零结果。

五、TIES-Merging

5.1 核心思想

TIES（Trim, Elect Sign, Merge）针对 Task Arithmetic 的符号冲突问题，通过三步策略系统性地解决参数干扰：

5.2 三步流程

步骤 1：修剪（Trim）

对每个任务向量进行稀疏化处理，只保留变化幅度最大的参数：

  • 根据参数绝对值排序，保留前 k% 的参数

  • 将其余参数重置为 0（或恢复预训练初始值）

  • 目的：消除对性能影响不大的冗余参数，减少合并干扰

步骤 2：选举（Elect Sign）

对每个参数位置，在所有模型中评估其符号方向：

  • 计算该参数在所有任务向量中的正负方向总和

  • 选择总和绝对值较大的方向作为共识符号

  • 丢弃与共识符号相反的参数贡献

步骤 3：不相交合并（Disjoint Merge）

在确定每个参数的最终符号后：

  • 仅合并与共识符号一致的参数值

  • 对这些一致值取平均

  • 不一致的贡献被完全丢弃

5.3 核心优势

  • 解决符号冲突：通过多数投票机制避免正负抵消

  • 保留关键信号：修剪步骤确保只有最具影响力的参数参与合并

  • 多模型扩展：天然支持三个及以上模型的合并

  • 稳定性强：在高 λ 值下仍保持较好性能

5.4 适用场景

  • 合并三个或更多模型时

  • 不同微调任务之间存在参数敏感区域重叠

  • 线性平均导致合并模型表现劣于任一父模型

六、DARE（Drop And REscale）

6.1 核心思想

DARE 从另一个角度解决参数干扰问题：微调产生的 delta 参数中，绝大多数是冗余的，真正对任务能力有贡献的参数只占很小比例。因此，可以大胆丢弃大部分 delta 参数，仅保留核心信号。

6.2 操作步骤

步骤 1：计算任务向量

xxxxxxxxxx
τ_i = θ_i^fine-tuned - θ^pretrained

步骤 2：随机丢弃（Drop）

以概率 p 随机将任务向量中的参数置零：

  • 典型丢弃率：p ∈ [0.5, 0.99]，实践中常用 0.9 甚至 0.99

  • 即保留仅 1% ~ 50% 的参数

步骤 3：重新缩放（Rescale）

将剩余参数乘以 1/(1-p) 进行缩放：

xxxxxxxxxx
τ_i^DARE = (1/(1-p)) × mask(τ_i, p)

目的：保持丢弃后期望值不变，补偿被丢弃参数的贡献。

6.3 为什么有效

现代语言模型具有高度过参数化的特性：

  • 微调过程中大部分参数更新对任务性能影响甚微

  • 丢弃 90% 甚至 99% 的 delta 参数后，模型仍能保持大部分微调能力

  • 稀疏化后的任务向量在合并时干扰大幅降低

6.4 注意事项

  • 密度参数调优：density（保留比例）低于 0.4 时可能过度剪枝，丢失真实任务信号

  • 建议起始值：density = 0.7，逐步降低并监控任务性能

  • 与 TIES 的关系：DARE 本身不是完整的合并方法，而是预处理步骤，通常与 Task Arithmetic 或 TIES 结合使用

七、DARE-TIES：组合方法

7.1 核心思想

DARE-TIES 是目前多模型合并的最佳通用方法，结合了两种技术的优势：

  • DARE：通过随机丢弃去除低信号噪声

  • TIES：通过符号选举解决剩余参数的冲突

7.2 工作流程

xxxxxxxxxx
模型A微调权重 ─┐
模型B微调权重 ─┼→ 计算任务向量 → DARE稀疏化 → TIES符号选举 → 合并 → 合并模型
模型C微调权重 ─┘

具体步骤：

  1. 为每个微调模型计算任务向量（与预训练基座的差）

  2. 对每个任务向量应用 DARE：随机丢弃 + 重新缩放

  3. 对稀疏化后的任务向量应用 TIES：修剪 → 选举符号 → 不相交合并

  4. 将合并后的任务向量加回预训练基座

7.4 参数调优指南

八、其他重要方法

8.1 Fisher-Weighted Merging

使用 Fisher 信息矩阵的对角线作为参数权重：

xxxxxxxxxx
θ_merged = Σ (F_i ⊙ θ_i) / Σ F_i

Fisher 对角线估计了参数扰动对模型输出分布的影响程度。对任务更重要的参数（Fisher 值更高）在合并中获得更大权重。适用于模型间参数重要性差异显著的场景。

8.2 RegMean

将合并问题建模为每层的最小二乘问题。对于线性层，利用输入激活的二阶矩矩阵 G_i 求解最优合并权重：

xxxxxxxxxx
W_merged = (Σ G_i)^(-1) × Σ (G_i × W_i)

"无数据"特性：G_i 是预计算统计量，无需训练循环。当各模型的输入分布差异较大时，RegMean 优于 Fisher-Weighted Merging。

8.3 进化模型合并（Evolutionary Model Merge）

使用进化优化算法（如 CMA-ES）搜索每层的最优合并系数：

  • 参数空间（PS）合并：为每层搜索混合权重 α_ℓ

  • 数据流空间（DFS）合并：为每层选择使用哪个源模型的层

以下游任务评估作为适应度函数，自动找到最优合并策略。代价是需要评估计算资源进行搜索。

8.4 Passthrough（直通/Frankenmerge）

与之前方法有本质不同：通过拼接不同模型的层构建新模型，可产生异构参数数量的模型（如用两个 7B 模型构建 9B 模型）。社区常称之为"弗兰肯斯坦模型"（Frankenmerge）。

十、工具与生态

10.1 Mergekit

Mergekit 是目前最主流的模型合并开源工具（5K+ GitHub Stars），实现了所有主流合并算法：

  • SLERP、TIES、DARE、DARE-TIES

  • Task Arithmetic、Linear、Passthrough

  • MoE（专家混合）架构构建

特点：

  • 纯 CPU 合并（无需 GPU）

  • 支持懒加载（--lazy-unpickle）降低内存占用

  • YAML 配置文件驱动

  • 与 HuggingFace 生态深度集成

硬件要求：

  • CPU 合并：RAM 是瓶颈，合并两个 7B bf16 模型需约 28GB RAM

  • GPU 合并：A100 40GB 可用于大规模模型

10.2 社区实践

HuggingFace 社区已托管数千个合并模型，常见实践包括：

  • 将通用指令模型与代码/数学/医疗等专业模型合并

  • 通过负权重移除模型的有害行为

  • 构建多领域能力的"全能"模型

  • 合并不同尺寸的 LoRA 适配器

十一、总结

模型合并技术的本质是在不增加训练成本的前提下，通过权重空间的数学操作实现知识组合。从最简单的线性平均到复杂的 DARE-TIES 组合策略，这些方法形成了一个由浅入深的技术谱系，为构建多能力融合的单一模型提供了高效、可解释的路径。在实际应用中，建议从 Task Arithmetic 或 TIES 起步，根据合并效果逐步尝试 DARE-TIES，并通过验证集评估确定最优的缩放系数和密度参数。
