领域数据构建与 SFT 数据工程

一、概述

监督微调（Supervised Fine-Tuning, SFT）是大语言模型适应特定领域的关键环节。高质量 SFT 数据直接决定了模型在领域任务上的表现和能力边界。领域数据构建是一个系统工程，涵盖数据需求分析、多源收集、清洗过滤、质量评估、去重脱敏、格式标准化等多个环节。本文系统介绍领域数据构建的全流程，重点覆盖指令微调数据构建、SFT 数据清洗与质量评估三大核心模块。

二、领域数据构建全流程

2.1 数据需求分析与任务定义

2.1.1 确定目标任务领域

构建领域数据的第一步是明确目标场景和任务类型：

  • 领域定位：医疗、法律、金融、教育、科研等垂直领域

  • 任务类型：知识问答、推理分析、代码生成、对话交互、摘要提取、多轮咨询等

  • 能力目标：领域知识注入、指令遵循能力、推理能力、多轮对话能力

2.1.2 设计指令模板系统

指令模板是 SFT 数据的核心骨架，需要覆盖：

  • 指令多样性：同一任务使用多种表述方式（如"请解释..."、"什么是..."、"分析以下..."）

  • 输入格式：支持纯文本、结构化数据、多模态输入等

  • 输出规范：定义答案格式、长度限制、风格要求（如学术严谨性、口语化程度）

  • 系统提示：定义模型角色和行为约束（如"你是一位医学专家"）

2.2 数据收集与生成策略

2.2.1 多源数据收集方法

2.2.2 LLM 辅助数据合成

当领域标注数据稀缺时，LLM 合成是核心策略：

三步合成流程：

  1. 领域关键词采样：从目标领域文献中统计高频关键词，构建概率分布表

  2. 任务描述设计：编制代表性任务列表，覆盖领域内的各种应用场景

  3. 指令生成：采样关键词 + 任务描述 → 提示强 LLM 生成上下文、问题与答案

质量控制：

  • 使用教师模型（如 Qwen3-235B-A22B、DeepSeek-V3）生成推理链（Chain-of-Thought）

  • 对生成结果进行答案正确性验证

  • 过滤格式错误、工具执行失败、答案错误的样本

三、SFT 数据清洗

3.1 清洗管道概览

xxxxxxxxxx
原始数据
    ├──→ 规则过滤（正则、关键词、黑名单）
    ├──→ 安全过滤（有害内容、隐私信息）
    ├──→ 格式校验（JSON 完整性、字段缺失）
    ├──→ 质量评分（LLM/规则打分）
    ├──→ 去重处理（精确 + 语义去重）
    ├──→ 长度过滤（过长/过短样本）
    ├──→ 语言一致性检查
    └──→ 脱敏处理（个人信息、敏感实体）
              ↓
         清洗后数据集

3.2 规则过滤

3.2.1 基础规则过滤

  • 正则表达式过滤：去除乱码、特殊字符、URL、邮箱、电话号码

  • 关键词黑名单：过滤包含暴力、色情、歧视、政治敏感等内容的样本

  • 格式校验：确保 JSON 结构完整、必要字段（instruction/output）存在

  • 拒绝模式过滤：去除包含"我无法回答"、"作为AI助手"等拒绝模板的样本

3.2.2 个人信息过滤

  • 身份证号、银行卡号、手机号等正则匹配

  • 人名、地址等 NER 实体识别后脱敏

  • 时间敏感信息过滤（如"昨天"、"上周"等相对时间）

3.3 安全过滤

  • 有害内容检测：使用安全分类器（如 Llama Guard、WildGuard）检测并过滤有害样本

  • 偏见检测：识别并过滤包含性别、种族、地域等偏见的样本

  • 对抗样本过滤：识别越狱尝试、提示注入等恶意输入

3.4 质量评分与过滤

3.4.1 LLM-based 质量评分

使用强 LLM（如 GPT-4、Llama-3-70B）从多维度评估样本质量：

过滤策略：

  • 仅保留平均分 ≥ 4 的样本

  • 对关键维度（如正确性）设置硬阈值（如 ≥ 4）

  • 对偏好对数据，仅保留偏好差距明显的样本（如 GPT-4 置信度 ≥ 0.6）

3.4.2 基于困惑度的质量过滤

  • 使用预训练模型计算样本困惑度（Perplexity）

  • 过滤 PPL 过高（语法混乱）或过低（过于简单/重复）的样本

  • 结合领域相关性评分，过滤与目标领域无关的内容

3.5 去重处理

3.5.1 精确去重

  • 哈希去重：使用 MD5/SHA256 计算样本哈希，完全相同的样本直接删除

  • N-gram 匹配：对评估基准进行 N-gram（通常 N=4~13）匹配，防止数据泄露

3.5.2 语义去重

  • 嵌入相似度：使用嵌入模型（如 BGE-M3、Qwen3-Embedding-8B、SentenceTransformer）将样本编码为向量

  • 相似度阈值：余弦相似度 > 0.95（严格）或 > 0.75（宽松）视为重复

  • MinHash LSH：使用局部敏感哈希进行大规模近似去重，计算效率高

实践要点：

  • 有害样本与无害样本分别去重后再合并，避免丢失边缘案例

  • 跨来源去重：不同开源数据集之间常有大量重叠

  • 对评估集进行语义相似度过滤：即使不是精确匹配，高度相似的样本也应移除

3.6 长度与格式过滤

  • 长度过滤：丢弃响应超过最大长度限制（如 2048 tokens）或双方均过短（如 < 32 tokens）的样本

  • 语言一致性：丢弃与主要语言不匹配的样本

  • 文本规范化：修复字符编码错误、标准化标点符号、统一换行符

3.7 领域特定过滤

3.7.1 多轮对话过滤

针对多轮对话数据，需额外评估：

  • 上下文相关性（Context Relevance, CR）：

    xxxxxxxxxx
    CR(H, T) = L_θ(t_i | H) / L_θ(t_i)

    • r > 1：历史信息对当前轮次有负面影响

    • r < 1：历史信息有正面影响，但过小表示上下文高度重复

  • 轮次间多样性：过滤各轮次内容过于相似的对话

3.7.2 代码数据过滤

  • 语法正确性检查（AST 解析）

  • 执行结果验证（单元测试）

  • 代码风格一致性检查

四、数据质量评估

4.1 质量评估维度

4.1.1 数据层面评估

4.1.2 分布层面评估

  • 主题平衡：使用主题标签模型（如 InsTag）对样本进行主题分类，确保各主题分布均衡

  • 难度平衡：将样本按难度分级（如 School/Student/Professor），确保各难度层级比例合理

  • 任务类型平衡：覆盖知识问答、推理、代码、写作等多种任务类型

  • 语言平衡：多语言场景下确保各语言比例适当

4.2 自动化质量评估方法

4.2.1 基于强模型的评估

  • 评委模型打分：使用 GPT-4、Claude 等强模型作为评委，对样本进行多维度评分

  • 交叉验证：多个评委模型打分不一致时，引入人工仲裁

  • 偏好对评估：对偏好数据，使用奖励模型评估偏好差距是否显著

4.2.2 基于统计的评估

  • 困惑度分布：绘制 PPL 分布图，识别异常区间

  • 长度分布：分析指令和响应的长度分布，识别异常值

  • 词汇丰富度：计算 Type-Token Ratio（TTR），评估词汇多样性

  • N-gram 重复率：检测模板化、重复性内容

4.2.3 基于模型的评估

  • 下游任务验证：在小型验证集上快速微调，评估模型性能

  • 数据影响力分析：使用 Data Shapley 或 Influence Functions 评估单个样本对模型性能的贡献

  • 错误模式分析：分析模型在验证集上的错误类型，反向追溯数据问题

4.3 人工评估

4.3.1 评估维度

  • 事实准确性：答案中的事实是否可验证且正确

  • 逻辑连贯性：推理过程是否严密、无跳跃

  • 表达清晰度：语言是否流畅、专业术语使用是否准确

  • 完整性：是否充分回答了问题，无遗漏关键信息

  • 安全性：是否包含有害、偏见或不当内容

4.3.2 评估流程

  1. 抽样策略：随机抽样 + 边界案例定向抽样

  2. 评分标准：制定详细的评分 rubric，确保评估者间一致性（Inter-Annotator Agreement > 0.8）

  3. 盲评机制：评估者不知道样本来源（人工/合成）

  4. 迭代反馈：将评估结果反馈到数据生成/清洗流程，形成闭环

4.4 去污染（Decontamination）

防止训练数据泄露到评估基准中：

  • N-gram 匹配：对常用评估基准（如 MMLU、GSM8K、HumanEval）进行 N-gram 匹配

  • 语义相似度过滤：使用嵌入模型检测与评估样本语义高度相似的训练样本

  • Top-K 相似过滤：对每个评估样本，过滤训练集中最相似的 Top-5 样本

五、数据增强与扩充

5.1 指令改写

  • 同义改写：使用 LLM 对指令进行多种表述改写，增加指令多样性

  • 风格转换：将同一问题转换为不同风格（学术、口语、技术文档）

  • 复杂度调整：对简单问题增加约束条件，对复杂问题简化表述

5.2 反向生成

  • 从答案生成问题：给定高质量答案，让模型生成对应的问题

  • 多问题生成：对同一上下文生成多个不同角度的问题

5.3 自我修正数据

  • 从执行失败的轨迹中采样，生成自我修正过程

  • 增强模型的错误识别和纠正能力

5.4 课程学习数据编排

  • 难度渐进：按难度从低到高排列训练数据

  • 领域渐进：从通用领域逐步过渡到专业领域

  • 长度渐进：从短序列逐步过渡到长序列

七、最佳实践与注意事项

7.1 核心原则

  1. 质量优于数量：10K 高质量样本 > 100K 低质量样本

  2. 多样性是关键：指令类型、难度、长度、风格均需多样化

  3. 渐进式构建：从小规模验证开始，逐步扩展

  4. 持续评估：建立自动化质量监控体系，定期抽检

  5. 版本控制：对数据集进行版本管理，记录每次变更

7.2 常见陷阱

7.3 数据混合策略

  • 领域:通用比例：通常 1:10 到 1:100，根据领域特殊性调整

  • 任务类型比例：根据目标能力分配（如推理 30%、知识 40%、对话 30%）

  • 难度比例：金字塔结构（简单 50%、中等 35%、困难 15%）

八、总结

领域数据构建是 SFT 成功的基石，其核心流程可概括为：

xxxxxxxxxx
需求分析 → 多源收集 → 合成增强 → 规则过滤 → 质量评分 → 
语义去重 → 安全过滤 → 去污染 → 人工审核 → 数据混合 → 版本发布

关键要点：

  • 数据质量 > 数据数量：严格的清洗和评估流程比单纯堆积数据更重要

  • 自动化 + 人工：利用 LLM 和规则实现大规模自动化处理，关键节点引入人工审核

  • 闭环迭代：将模型评估结果反馈到数据构建流程，持续优化数据质量

  • 去污染不可少：防止评估基准泄露是确保结果可信的前提

高质量领域 SFT 数据的标准是：事实准确、逻辑严密、表达清晰、格式规范、分布均衡、安全无害。只有经过系统化的构建、清洗和评估流程，才能为领域大模型的训练奠定坚实基础。
