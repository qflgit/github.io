全参数微调策略详解

一、概述

全参数微调（Full Parameter Fine-Tuning）是指对预训练模型的所有可训练参数进行更新，使其适应特定下游任务或领域。与参数高效微调（PEFT，如 LoRA、Adapter）仅更新少量参数不同，全参数微调能够最大程度地释放模型的领域适配能力，但代价是更高的计算资源需求和更复杂的训练策略。

1.1 适用场景

1.2 核心挑战

  • 显存瓶颈：全参数更新需要存储模型参数、梯度、优化器状态，显存需求约为模型参数量的 12~16 倍（FP32）

  • 训练不稳定：大模型微调容易出现梯度爆炸、损失震荡、灾难性遗忘

  • 过拟合风险：参数全部更新，在小数据集上容易过拟合

  • 训练效率：需要精心设计学习率、批次大小、精度策略以加速收敛

二、学习率调度（Learning Rate Scheduling）

学习率是最关键的超参数之一。全参数微调中，学习率通常比预训练阶段低 1~2 个数量级，且需要配合精细的调度策略。

2.1 Warmup（预热阶段）

2.1.1 为什么需要 Warmup

训练初期，模型参数尚未适应新任务分布，直接使用高学习率会导致：

  • 梯度方向不稳定，参数更新剧烈震荡

  • 损失值剧烈波动甚至发散（NaN）

  • 预训练知识被过早破坏

Warmup 在训练开始阶段线性或指数式地逐步提升学习率，让模型平稳进入训练状态。

2.1.2 Warmup 策略

线性 Warmup：

lr = base_lr * min(1.0, current_step / warmup_steps)

指数 Warmup：

xxxxxxxxxx
lr = base_lr * (current_step / warmup_steps)^2

配置建议：

  • Warmup 步数：通常为总训练步数的 3%~10%，或固定 500~1000 步

  • 对于全参数微调，warmup_ratio=0.03（3%）是常见默认值

  • 数据量较大时，可适当延长 warmup 至总步数的 10%

2.2 学习率衰减策略

2.2.1 Cosine Annealing（余弦退火）

最常用的衰减策略，学习率按余弦曲线平滑下降：

xxxxxxxxxx
lr = min_lr + 0.5 * (max_lr - min_lr) * (1 + cos(π * current_step / total_steps))

特点：

  • 前期下降缓慢，保留较高学习率进行充分探索

  • 后期快速下降，精细调整参数

  • 对 Transformer 大模型训练效果通常最佳

  • 全参数微调推荐首选

2.2.2 Linear Decay（线性衰减）

xxxxxxxxxx
lr = max_lr * (1 - current_step / total_steps)

特点：

  • 学习率匀速下降，计算简单

  • 适合训练步数可精确预估的场景

  • 在微调后期可能下降过快，导致欠拟合

2.2.3 Polynomial Decay（多项式衰减）

xxxxxxxxxx
lr = (max_lr - min_lr) * (1 - current_step / total_steps)^power + min_lr

特点：

  • 通过 power 参数控制衰减曲线形状

  • power=1 时为线性，power=2 时前期衰减更慢

2.2.4 Constant with Warmup（恒定学习率）

xxxxxxxxxx
lr = base_lr  # warmup 结束后保持恒定

特点：

  • 适合数据量极大、训练步数极长的场景

  • 在微调中较少使用，除非数据量远超常规

2.3 学习率配置参考

经验法则：

  • 全参数微调的学习率通常比 LoRA 微调低 1~2 个数量级（LoRA 常用 2e-4，全参数常用 1e-5）

  • BF16 训练可承受略高的学习率（比 FP16 高约 20%~50%）

  • 数据量越大，学习率可适当提高；数据量越小，学习率应降低

三、梯度累积（Gradient Accumulation）

3.1 核心思想

梯度累积通过将大批次（Global Batch）拆分为多个小批次（Micro Batch），在每个小批次上计算梯度但不立即更新参数，而是累积多个小批次的梯度后统一执行一次参数更新。

3.2 数学原理

​x
# 标准训练（大 batch）
loss = criterion(model(big_batch))
loss.backward()
optimizer.step()  # 每步更新


# 梯度累积（小 batch × N 步）
for i in range(accumulation_steps):
    loss = criterion(model(micro_batch))
    loss = loss / accumulation_steps  # 缩放损失
    loss.backward()  # 累积梯度
optimizer.step()  # N 步后统一更新
optimizer.zero_grad()

关键公式：

xxxxxxxxxx
Global Batch Size = per_device_batch_size × num_gpus × gradient_accumulation_steps

3.3 为什么有效

  • 模拟大批量训练：大批量训练提供更稳定的梯度估计，收敛更快、泛化更好

  • 突破显存限制：单卡无法容纳大 batch 时，通过累积实现等效效果

  • 通信效率：在分布式训练中，减少 all-reduce 通信频率

3.4 配置策略

注意事项：

  • 梯度累积步数增加时，需相应调整学习率（通常按 sqrt(global_batch) 或线性比例调整）

  • 损失值需除以 accumulation_steps，确保梯度尺度一致

  • 过大的累积步数（>32）可能引入数值误差

3.5 与数据并行结合

在多 GPU 分布式训练中：

xxxxxxxxxx
Global Batch = per_device_batch_size × num_gpus × gradient_accumulation_steps × num_nodes

DeepSpeed ZeRO 等框架会自动处理梯度累积与分布式通信的协调。

四、混合精度训练（Mixed Precision Training）

4.1 为什么需要混合精度

全参数微调大模型时，显存是最大瓶颈。FP32（32位浮点）训练需要存储：

  • 模型参数：4 bytes/参数

  • 梯度：4 bytes/参数

  • 优化器状态（Adam）：8 bytes/参数（一阶矩 + 二阶矩）

  • 激活值：与序列长度和 batch size 相关

总计约 16~20 bytes/参数。一个 7B 模型全参数 FP32 训练需要约 112~140GB 显存，远超单卡容量。

4.2 FP16（半精度浮点）

4.2.1 原理

FP16 使用 16 位表示浮点数（1 位符号 + 5 位指数 + 10 位尾数）：

  • 显存占用减半：2 bytes/参数

  • 计算速度提升：Tensor Core 对 FP16 有硬件加速

  • 7B 模型显存需求降至约 56~70GB

4.2.2 动态损失缩放（Dynamic Loss Scaling）

FP16 的动态范围有限（~5.96e-8 到 65504），容易出现梯度下溢（Underflow，梯度变为 0）：

xxxxxxxxxx
# 动态损失缩放流程
1. 前向传播，计算损失
2. 损失 × loss_scale（如 2^16 = 65536）
3. 反向传播，计算梯度
4. 检查梯度是否包含 Inf/NaN
   - 是：loss_scale 减半，跳过更新，重新计算
   - 否：梯度 ÷ loss_scale，正常更新
5. 若连续 N 步无溢出，loss_scale 倍增

常见问题：

  • "Gradient overflow. Skipping step. Loss scaler reducing loss scale to ..."

  • 当 loss_scale 持续下降至 1 以下，训练可能不稳定

4.3 BF16（Brain Floating Point 16）

4.3.1 原理

BF16 使用 16 位表示（1 位符号 + 8 位指数 + 7 位尾数）：

  • 指数位与 FP32 相同（8 位），动态范围与 FP32 相当

  • 尾数位减少（7 位），精度略低于 FP16

  • 无需动态损失缩放，数值稳定性显著优于 FP16

4.3.2 FP16 vs BF16 对比

4.3.3 BF16 实践要点

  • 2026 年标准：A100/H100/B200 等现代 GPU 上，BF16 是默认推荐

  • 学习率调整：BF16 可承受略高学习率（比 FP16 高约 20%~50%）

  • 无需损失缩放：简化训练配置，减少调试复杂度

  • 显存节省：与 FP16 相同的 2 bytes/参数

4.4 TF32（Tensor Float 32）

TF32 是 NVIDIA Ampere 架构引入的混合精度格式：

  • 内部计算使用 FP32，但 Tensor Core 以 TF32 精度加速

  • 无需修改代码，自动生效

  • 速度接近 FP16/BF16，但精度接近 FP32

  • 适合对数值稳定性要求极高且不想处理混合精度复杂性的场景

五、梯度裁剪（Gradient Clipping）

5.1 为什么需要梯度裁剪

全参数微调大模型时，梯度爆炸是常见问题：

  • 某些样本的梯度范数异常大，导致参数更新剧烈

  • 混合精度训练中，损失缩放不当可能放大梯度

  • 长序列训练时，梯度随序列长度累积

梯度裁剪通过限制梯度的最大范数，防止单次更新幅度过大。

5.2 裁剪方法

5.2.1 按范数裁剪（Norm Clipping）

xxxxxxxxxx
# PyTorch 实现
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

如果梯度范数超过 max_norm，则按比例缩放整个梯度向量：

xxxxxxxxxx
if ||g|| > max_norm:
    g = g × (max_norm / ||g||)

5.2.2 按值裁剪（Value Clipping）

xxxxxxxxxx
torch.nn.utils.clip_grad_value_(model.parameters(), clip_value=1.0)

将每个梯度元素的绝对值限制在 clip_value 以内。

六、其他关键优化策略

6.1 梯度检查点（Gradient Checkpointing）

6.1.1 原理

标准反向传播需要缓存所有中间激活值以计算梯度。梯度检查点通过只保存部分层的激活值，在反向传播时重新计算被丢弃的激活值，以计算时间换取显存空间。

xxxxxxxxxx
标准训练：显存 = 模型参数 + 梯度 + 优化器状态 + 全部激活值
检查点训练：显存 = 模型参数 + 梯度 + 优化器状态 + 部分激活值
           代价：约 20%~30% 额外前向计算时间

6.1.2 配置

xxxxxxxxxx
model.gradient_checkpointing_enable()
# 或在 TrainingArguments 中
gradient_checkpointing=True

适用场景：

  • 显存不足但可接受训练速度下降

  • 长序列训练（激活值占显存大头）

  • 与梯度累积配合，最大化有效 batch size

6.2 优化器选择

AdamW 配置：

xxxxxxxxxx
optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=1e-5,
    betas=(0.9, 0.999),
    eps=1e-8,
    weight_decay=0.01  # 权重衰减，防止过拟合
)

6.3 权重衰减（Weight Decay）

  • 在 AdamW 中，weight_decay 直接作用于参数更新（而非梯度）

  • 全参数微调推荐值：0.01 ~ 0.1

  • 数据量小时增大 weight_decay（如 0.1），数据量大时可减小（如 0.01）

  • 注意：bias 和 LayerNorm 参数通常不应用 weight_decay

6.4 分布式训练策略

6.4.1 DeepSpeed ZeRO

ZeRO（Zero Redundancy Optimizer）将优化器状态、梯度和参数分片到多 GPU：

全参数微调 70B 模型示例：

  • 8×A100 80GB + ZeRO-3：可实现全参数微调

  • 配合梯度检查点和 BF16，进一步优化显存

6.4.2 FSDP（Fully Sharded Data Parallel）

PyTorch 原生的全分片数据并行：

  • 与 ZeRO-3 类似，将参数、梯度、优化器状态分片

  • 更灵活的 API，与 PyTorch 生态深度集成

  • 适合 13B~70B 模型的全参数微调

6.5 训练轮数与早停

  • 全参数微调通常 1~3 个 epoch 即可

  • 数据量极大（>100K 样本）时，1 个 epoch 往往足够

  • 监控验证集损失，采用早停（Early Stopping）防止过拟合

  • 保存多个 checkpoint，选择验证集表现最佳的模型

九、总结

全参数微调的核心在于精细控制训练动态：通过 Warmup 平稳启动、Cosine 退火精细收敛、梯度累积模拟大批量、混合精度突破显存瓶颈、梯度裁剪保证稳定性。这些技术的组合使用，使得在合理硬件配置下（如 8×A100 80GB），即使是 70B 级别的模型也能实现高效的全参数微调。
