1. 量化基础概念

1.1 为什么需要量化

大语言模型（LLM）的参数规模呈指数级增长——从 GPT-2 的 15 亿参数，到 LLaMA-3.1-405B 的 4050 亿参数，再到 DeepSeek-V3 的 6710 亿参数。然而，GPU 显存容量的增长速度远不及模型规模的扩张速度。

以 FP16 精度存储 70B 模型需要约 140GB 显存，而一块 H100 SXM5 的显存仅为 80GB。量化技术通过降低模型数值精度，将 FP16/FP32 权重和激活值映射到低比特整数空间（如 INT8/INT4），可将模型显存压缩至原先的 1/2 至 1/4，同时利用硬件加速实现 1.5-3 倍的推理速度提升。

1.2 量化对象

在 LLM 部署推理中，量化对象主要包括三类：

  • 权重量化（Weight Quantization）：仅对模型权重进行量化，常见格式为 W4A16（权重 INT4，激活 FP16）或 W8A16（权重 INT8，激活 FP16）

  • 激活量化（Activation Quantization）：对前向传播中的激活值进行量化，常见格式为 W8A8（权重和激活均为 INT8）

  • KV Cache 量化：对 Attention 机制中的 Key/Value 缓存进行量化，缓解长上下文推理时的显存瓶颈

2. INT8 / INT4 量化

2.1 INT8 量化

INT8 量化将 FP16/BF16 的权重或激活值映射到 8 位整数空间 [-128, 127]，存储空间减半。其实现方式主要有两种：

对称量化（Symmetric Quantization）：

scale = max(abs(tensor)) / 127
quantized = round(tensor / scale)
dequantized = quantized * scale

非对称量化（Asymmetric Quantization）：引入零点（zero-point）处理非零中心分布：

xxxxxxxxxx
scale = (max(tensor) - min(tensor)) / 255
zero_point = round(-min(tensor) / scale)
quantized = round(tensor / scale) + zero_point

INT8 量化的核心挑战在于激活值的异常值（outliers）——Transformer 中的某些通道会呈现极大的激活幅度，导致整体 scale 过大，普通数值被压缩到很小的范围，造成精度损失。

2.2 INT4 量化

INT4 量化将数值映射到 4 位整数空间 [-8, 7]，存储空间仅为 FP16 的 1/4。由于表示范围极其有限，INT4 必须采用分组量化（Group-wise Quantization）策略：

  • 将权重矩阵按列（或块）划分为若干组（常见 group_size = 32/64/128）

  • 每组独立计算 scale 和 zero_point

  • 组内共享量化参数，组间保持独立

INT4 的精度损失通常比 INT8 更明显（1-3%），但在大多数任务上仍然可用，是消费级 GPU（24GB 显存）运行 70B 模型的唯一可行方案。

3. GPTQ：基于 Hessian 的逐层量化

3.1 核心思想

GPTQ（Generative Pre-trained Transformer Quantization）的思想根植于 1990 年代的"最优脑损伤"（Optimal Brain Damage）理论——利用 Hessian 矩阵来量化每个参数对损失的影响，从而有针对性地压缩对结果影响最小的权重。

论文：GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers（Frantar et al., 2022, ETH Zurich）

3.2 数学原理

对于某层权重矩阵 W ∈ R^(d_out × d_in)，设输入激活为 X，则量化后的重构误差为：

xxxxxxxxxx
E = ||WX - ŴX||²₂

其中 Ŵ 为量化后的权重。GPTQ 的目标是找到最优 Ŵ 使得 E 最小，同时约束 Ŵ 为低精度整数。

关键步骤：

  1. 收集校准数据：从训练集中取少量样本（通常 128 个）作为校准集

  2. 计算 Hessian 矩阵：H = 2XX^T ∈ R^(d_in × d_in)

  3. 逐列量化：将权重矩阵按列依次量化，量化第 q 列后，利用 H 计算误差并更新剩余列以补偿

核心更新公式：

xxxxxxxxxx
delta_W[q+1:] -= err_q * H[q, q+1:] / H[q, q]

  1. Lazy Batching：将 128 列作为一批并行处理，避免逐列 GPU 同步开销

  2. Cholesky 分解预处理：对 H 的逆矩阵做 Cholesky 分解，提升数值稳定性

3.3 特点与局限

  • 优点：无需重新训练（PTQ），支持 INT4/INT8，压缩率高

  • 局限：

    • 主要压缩权重，激活值保持 FP16（W4A16），无法减少激活显存

    • 量化过程需要计算 Hessian 矩阵，对超大模型（>100B）内存开销较大

    • 早期实现不提供计算加速（仅减少显存），需配合 Marlin/ExLlamaV2 等内核实现加速

4. AWQ：激活感知权重量化

4.1 核心思想

AWQ（Activation-aware Weight Quantization）的核心洞见是：并非所有权重通道同等重要。那些对应大激活幅度的权重通道对模型输出影响更大，应当给予更高保护。

论文：AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration（Lin et al., 2023, MIT）

4.2 技术原理

AWQ 通过逐通道缩放（Channel-wise Scaling）来保护重要权重：

  1. 激活感知：分析输入激活的分布，识别出具有大异常值的通道

  2. 重要性加权：为不同通道分配不同的量化保护级别——对应大激活的通道使用更精细的量化粒度

  3. 硬件友好：缩放因子被设计为 2 的幂次（如 1, 2, 4, 8...），可通过位运算实现，不引入额外计算开销

量化公式：

​x
# 原始线性层
Y = X · W


# 引入逐通道缩放因子 s（激活感知）
Y = (X · diag(s)) · (diag(s)^(-1) · W) = X' · W'


# 对 W' 进行 INT4 量化，s 在推理时预先融合到权重中

4.4 实际表现

在 Llama-3-70B 上的实测数据：

  • AWQ (W4A16)：PPL 6.84，MMLU 66.2%（相比 FP16 下降 3.4%）

  • GPTQ (W4A16)：PPL 6.90，MMLU 65.8%（相比 FP16 下降 3.9%）

AWQ 在精度上略优于 GPTQ，且推理速度通常更快（尤其在 H100 上使用 Marlin-AWQ 内核时）。

5. SmoothQuant：激活异常值平滑迁移

5.1 问题背景

INT8 量化的最大难点在于激活值而非权重。Transformer 中的激活分布存在严重的异常值（outliers）——少数通道的激活幅度是普通通道的 20-100 倍，导致整体量化尺度被拉大，大部分数值被压缩到极低精度。

5.2 核心思想：难度迁移

SmoothQuant 的洞见极具优雅性：激活值难以量化，但权重容易量化；可以将激活值的"难度"通过等效变换迁移给权重。

论文：SmoothQuant: Accurate and Efficient Post-Training Quantization for Large Language Models（Xiao et al., 2023, MIT）

对于线性层 y = x · W，引入逐通道平滑因子 s ∈ R^(C_in)：

xxxxxxxxxx
y = (x · diag(s)^(-1)) · (diag(s) · W) = x' · W'

通过选取合适的 s，使得：

  • x'（新激活）的异常值被抑制，易于 INT8 量化

  • W'（新权重）虽然数值范围增大，但仍可被 INT8 表示

平滑因子计算公式：

xxxxxxxxxx
s_j = max(|x_j|)^α / max(|W_j|)^(1-α),  α ∈ [0, 1]

  • α = 1：所有难度转移给权重，激活量化最简单

  • α = 0：保持不变

  • α = 0.5：难度平均分配（实践中常用，平衡精度与效率）

5.3 W8A8 推理加速

SmoothQuant 实现真正的 W8A8 量化（权重和激活均为 INT8），其加速来源于：

  • INT8 张量核心的矩阵乘法计算加速：相比 FP16，INT8 矩阵乘法吞吐量翻倍

  • 内存带宽减半：权重和激活均为 1 字节，减少数据搬运量

特别适合：

  • 预填充（Prefill）阶段：处理长序列时 batch size 大，计算密集型

  • 大批量推理：吞吐量优先场景

在 OPT-175B 上：W8A8 相比 FP16，内存节省 2 倍，吞吐量提升约 1.65 倍，精度几乎无损失。

5.4 离线吸收

平滑变换 W' = diag(s) · W 可在推理前预先计算并存储（类似 Batch Normalization Folding），推理时无额外开销。激活的缩放 x' = x · diag(s)^(-1) 可在运行时动态完成，计算量极小。

7. 工程实践与代码示例

7.1 使用 AutoAWQ 量化模型

xxxxxxxxxx
# pip install autoawq
from awq import AutoAWQForCausalLM
from transformers import AutoTokenizer


model_path = "meta-llama/Llama-3.1-8B-Instruct"
quant_path = "./llama3.1-8b-awq-w4"


# 加载模型和 tokenizer
tokenizer = AutoTokenizer.from_pretrained(model_path, trust_remote_code=True)
model = AutoAWQForCausalLM.from_pretrained(
    model_path,
    low_cpu_mem_usage=True,
    use_cache=False
)


# AWQ 量化配置
quant_config = {
    "zero_point": True,    # 非对称量化
    "q_group_size": 128,   # 分组大小，平衡精度和速度
    "w_bit": 4,           # 4 位量化
    "version": "GEMM",    # 可选 GEMM/GEMV
}


# 准备校准数据
from datasets import load_dataset
data = load_dataset("pileval", split="validation")
calib_data = tokenizer("\n\n".join(data[:128]["text"]), return_tensors="pt")


# 执行量化（约 5-10 分钟，8B 模型单卡 A100）
model.quantize(
    tokenizer,
    quant_config=quant_config,
    calib_data=calib_data,
)


# 保存量化模型
model.save_quantized(quant_path)
tokenizer.save_pretrained(quant_path)
print(f"量化完成！保存至 {quant_path}")

7.2 使用 AutoGPTQ 量化模型

xxxxxxxxxx
# pip install auto-gptq
from auto_gptq import AutoGPTQForCausalLM, BaseQuantizeConfig
from transformers import AutoTokenizer
import torch


model_path = "meta-llama/Llama-3.1-8B-Instruct"


# GPTQ 量化配置
quantize_config = BaseQuantizeConfig(
    bits=4,              # 量化位宽
    group_size=128,      # 分组量化，每 128 个参数一个 scale
    damp_percent=0.01,  # Hessian 矩阵正则化系数
    desc_act=False,     # 是否按激活降序排列权重（精度更高但更慢）
    sym=False,          # 非对称量化（zero_point != 0）
)


tokenizer = AutoTokenizer.from_pretrained(model_path, use_fast=True)
model = AutoGPTQForCausalLM.from_pretrained(model_path, quantize_config)


# 准备校准数据（建议 128 条，覆盖各种文本类型）
examples = [
    tokenizer("GPTQ is a quantization method for LLMs", return_tensors="pt"),
    tokenizer("The Transformer architecture uses attention mechanism", return_tensors="pt"),
    # ... 更多样本
]


# 执行量化（8B 模型约需 15 分钟）
model.quantize(examples)


# 保存
model.save_quantized("./llama3.1-8b-gptq-4bit", use_safetensors=True)

7.4 SmoothQuant 量化示例

xxxxxxxxxx
# pip install smoothquant
from smoothquant.smooth import smooth_lm
from smoothquant.calibration import get_act_scales
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch


model_path = "facebook/opt-6.7b"
tokenizer = AutoTokenizer.from_pretrained(model_path)
model = AutoModelForCausalLM.from_pretrained(
    model_path,
    torch_dtype=torch.float16,
    device_map="auto"
)


# 第一步：收集激活统计量（用于确定平滑因子）
act_scales = get_act_scales(model, tokenizer, dataset, num_samples=512)


# 第二步：应用平滑变换（修改权重，将激活难度迁移到权重）
smooth_lm(model, act_scales, alpha=0.5)  # alpha=0.5 为平衡点


# 第三步：W8A8 量化
from smoothquant.fake_quant import quantize_opt
model_w8a8 = quantize_opt(model, weight_quant="per_channel", act_quant="per_token")


# 推理（速度接近原生 INT8 张量核心）
inputs = tokenizer("Hello, SmoothQuant!", return_tensors="pt").to("cuda")
with torch.no_grad():
    outputs = model_w8a8.generate(**inputs, max_new_tokens=50)
print(tokenizer.decode(outputs[0]))

8. 量化局限性及注意事项

8.1 精度敏感场景

以下场景量化需谨慎，建议使用更高精度（INT8 而非 INT4，或保留 FP16）：

  • 数学推理任务：量化对精确计算影响更大，数值误差会累积

  • 代码生成：语法细节错误可能增加，括号匹配、缩进等容易出错

  • 低资源语言：训练数据少的语言精度损失更大

  • 超小模型（<7B）：量化收益有限，精度损失相对更大

8.2 幻觉（Hallucination）风险

研究表明，随着精度下降，模型幻觉率会上升，尤其在罕见实体和数值事实上。高 stakes 部署应使用更高精度或采用量化感知缓解策略。

8.3 评估建议

不要仅依赖 Benchmark 分数（如 MMLU、C-Eval），应在业务真实数据集上进行：

  • 困惑度（Perplexity）测试

  • 端到端任务准确率测试

  • 人工抽检输出质量

9. 总结

量化技术让大模型从"云端专属"变成了"本地可用"。2026 年，主流量化方案已经相当成熟：AWQ/GPTQ 用于 GPU 推理，GGUF+Ollama 用于 CPU/本地部署，SmoothQuant W8A8 用于大批量生产推理。选择适合场景的量化方案，是 AI 工程师降低部署成本、扩展应用边界的必备技能。
