1. RAG概述

检索增强生成（Retrieval-Augmented Generation, RAG）是一种将外部知识检索与大型语言模型（LLM）生成相结合的技术范式。其核心思想是：在LLM生成回答之前，先从外部知识库中检索相关文档或片段，将这些检索结果作为上下文注入到提示中，从而引导LLM生成更准确、更可靠、更具事实依据的回答。

RAG的价值在于：

  • 缓解幻觉：LLM基于检索到的真实文档生成，减少编造事实

  • 知识更新：无需重新训练模型即可更新知识库

  • 可溯源：回答可追溯至具体文档来源

  • 成本效益：相比微调大模型，RAG部署成本更低

2.3 检索器与重排序的协同工作流

检索器与重排序器的协同是RAG系统的核心，其工作流程分为两个阶段：

第一阶段：检索（Recall）

  • 目标：高召回率，尽可能不遗漏相关文档

  • 方法：使用轻量级双编码器（Bi-Encoder）或BM25进行大规模召回

  • 输出：Top-K候选文档（通常K=50~100）

第二阶段：重排序（Reranking）

  • 目标：高精度，将最相关的文档排在前面

  • 方法：使用计算成本更高的交叉编码器（Cross-Encoder）或LLM进行精排

  • 输出：Top-N最终文档（通常N=5~10）

协同优势：

  • 检索阶段注重速度，重排序阶段注重精度

  • 两阶段分离使系统可扩展：可以先用快速检索器过滤大量文档，再用昂贵模型精排少量候选

  • 重排序可以纠正检索阶段的错误，提升最终质量

# 检索 + 重排序协同示例
from langchain.retrievers import ContextualCompressionRetriever

# 1. 检索阶段（快速召回）

)


# 3. 生成
results = compression_retriever.get_relevant_documents(query)
answer = llm.generate(context=results, query=query)

3. 检索器技术详解

3.1 稀疏检索

BM25（Best Match 25）

  • 基于词频和逆文档频率的经典信息检索算法

  • 擅长精确词汇匹配，计算效率高

  • 对罕见实体和术语匹配效果好

  • 无法理解语义相似性（如"汽车"和"轿车"）

TF-IDF

  • 词频-逆文档频率加权

  • 简单高效，但效果不如BM25

3.2 密集检索

双编码器（Bi-Encoder）

  • 使用预训练语言模型（如BERT、Sentence-BERT）将查询和文档分别编码为向量

  • 通过余弦相似度或点积计算相关性

  • 速度快，可预先计算文档向量

  • 但查询和文档独立编码，交互信息有限

3.3 混合检索

Reciprocal Rank Fusion（RRF）

  • 将稀疏检索和密集检索的结果融合

  • 公式：score = Σ 1/(k + rank)，k通常为60

  • 综合了词汇匹配和语义理解的优势

  • 当前RAG系统的主流范式

加权融合：

xxxxxxxxxx
# 混合检索示例
sparse_results = bm25_retriever.retrieve(query, k=50)
dense_results = vector_retriever.retrieve(query, k=50)


# RRF融合
fused_results = reciprocal_rank_fusion(
    [sparse_results, dense_results],
    k=60
)

3.4 查询预处理

查询重写（Query Rewriting）

  • 修复歧义、解析代词、对齐索引内容

  • 使查询更清晰，提高检索匹配度

查询扩展（Query Expansion）

  • 使用LLM生成相关查询变体

  • 增加检索覆盖面

查询分解（Query Decomposition）

  • 将复杂多跳问题分解为顺序子查询

  • 每个子查询独立检索

  • 适合复杂推理场景

HyDE（Hypothetical Document Embeddings）

  • 生成合成答案作为查询

  • 弥合查询与文档之间的语义差距

  • 在零样本检索中效果显著

4. 重排序技术详解

4.1 重排序的必要性

检索器（尤其是双编码器）存在以下局限：

  • 查询和文档独立编码，缺乏细粒度交互

  • 对长文档的局部相关性判断不足

  • 无法处理跨段落推理（如共指消解、实体消歧）

重排序器通过更精细的交互建模来解决这些问题。

4.2 交叉编码器重排序

原理：将查询和文档拼接后输入单个Transformer模型，通过自注意力机制实现细粒度交互。

优势：

  • 查询和文档深度交互，精度显著高于双编码器

  • 可以捕捉复杂的语义关系

劣势：

  • 计算成本高，无法预先计算

  • 每次查询需要实时编码所有候选文档

  • 通常用于Top-K候选的精排（K=50~100）

主流重排序模型：

4.3 上下文感知重排序

EBCAR（Embedding-Based Context-Aware Reranker）

  • 直接在检索到的片段嵌入上操作

  • 通过结构信息和混合注意力机制增强跨段落理解

  • 捕获文档间的高级交互和文档内的低级关系

  • 在ConTEB基准上证明对跨段落推理有效

  • 轻量级框架，准确率和效率兼顾

技术特点：

  • 利用 passages 的结构信息

  • 混合注意力机制：跨文档交互 + 文档内关系

  • 无需昂贵的LLM推理，基于嵌入即可实现

4.4 依赖感知重排序

PankRAG的依赖感知重排序机制

  • 利用已解析的子问题依赖关系来增强和验证当前未解析子问题的检索内容

  • 通过全局感知层次解析路径捕获并行和递进关系

  • 引导LLM通过层次推理路径解析查询

  • 在复杂查询中，子问题之间存在依赖关系，重排序时考虑这些依赖可提升整体回答质量

5. RAG技术演进

5.1 Naive RAG

特点：

  • 基础向量检索 + 直接生成

  • 简单三段式：索引 → 检索 → 生成

  • 无查询优化、无重排序、无上下文处理

局限：

  • 检索质量直接决定生成质量

  • 对复杂查询效果差

  • 容易引入噪声文档

  • 上下文窗口浪费严重

5.2 Advanced RAG

改进点：

  • 查询优化：重写、扩展、分解

  • 重排序：Cross-Encoder精排

  • 上下文压缩：去除冗余信息

  • 混合检索：BM25 + 向量融合

  • 元数据过滤：利用文档元数据提升检索精度

效果：相比Naive RAG，召回率提升15-25%，幻觉率降低30-40%。

5.3 Modular RAG

特点：

  • 多路召回 + 融合

  • 模块化设计，各组件可独立优化和替换

  • 支持多种检索策略并行执行

典型模块：

  • 向量检索模块

  • 关键词检索模块

  • 图检索模块

  • 结构化数据查询模块

  • 时序检索模块

  • 跨模态检索模块

5.4 Agentic RAG

核心思想：检索不再是固定动作，而是动态决策过程。系统根据查询复杂度、模型置信度、历史交互自动调整检索策略。

典型架构：

  • Query Router：将查询分类为事实型/推理型/闲聊型，路由到不同处理管道

  • Confidence Gating：LLM自评估置信度，低置信度触发多路检索，高置信度直接生成

  • Iterative Refinement：检索结果矛盾时，自动发起澄清追问或二次检索

  • Self-Verification：生成后自我验证，发现错误自动重新检索和生成

价值：延迟与准确率的帕累托最优，企业级Agent的标配组件。

6. 2026年最新技术

6.1 多模态RAG（MM-RAG）

核心思想：打破"文本即一切"的假设，将PDF扫描件、架构图、数据表格、音频纪要纳入统一检索空间。

技术路径：

  • 使用多模态编码器（如SigLIP、Qwen2-VL、InternVL）将图像/表格转为统一语义向量

  • 结合OCR与版面分析（Layout Parser）保留空间结构

  • 检索时采用跨模态相似度匹配

  • 生成时注入视觉上下文

端到端多模态方案：

  • 阿里巴巴Qwen3-VL-Embedding：2048维统一向量空间，文本、图片、图文混合内容共享同一表示

  • 动态分辨率支持，自适应处理不同尺寸图片

  • Instruction-aware encoding：支持任务指令引导

6.2 GraphRAG

核心思想：将文档解析为知识图谱（实体-关系网络），支持多跳推理和复杂关系查询。

技术实现：

  1. 实体与关系提取：从文档中提取实体和关系

  2. 知识图谱构建：构建实体-关系网络

  3. 社区摘要：使用Leiden算法生成知识域的高层摘要

  4. 查询时：结合图结构进行局部搜索或全局搜索

微软GraphRAG实现：

优势：

  • 支持多跳推理（"A的老板的老板是谁？"）

  • 社区摘要提供全局视角

  • 适合法律文档、医疗知识库、代码库分析

PankRAG增强：

  • 全局感知层次解析路径：捕获并行和递进关系

  • 依赖感知重排序：利用子问题依赖关系验证检索内容

  • 在复杂查询中显著优于传统GraphRAG

6.3 自适应RAG

核心思想：检索不再是固定动作，而是根据查询特征动态决策。

技术组件：

  • Query Router：分类查询类型（事实型/推理型/闲聊型）

  • Confidence Gating：LLM自评估置信度，动态触发检索

  • Iterative Refinement：检索结果矛盾时自动二次检索

  • Self-RAG：通过反射token动态判断是否需要检索

Self-RAG机制：

  • [Retrieve] token：判断是否需要检索

  • [IsRel] token：判断检索结果是否相关

  • [IsSup] token：判断生成内容是否有依据

  • 效果：比普通RAG幻觉率降低40%

6.4 分层RAG

核心思想：从"平铺切块"升级为"树状索引"。先检索文档大纲/摘要层，定位到具体章节，再细粒度提取片段。

实现方式：

  • 双级向量库：Summary层 + Chunk层

  • 树索引（Tree Index）：文档结构化为树状索引

  • LLM自动摘要路由：基于摘要进行粗粒度定位

优势：

  • 显著降低无效Token输入，节省推理成本

  • 保留长文档的宏观语义结构

  • 解决"大海捞针"与上下文窗口浪费问题

6.5 自我反思RAG（Self-RAG）

核心思想：模型在生成过程中动态判断检索和生成质量。

工作流程：

  1. 生成[Retrieve] token，判断是否需要检索

  2. 如需检索，执行检索并生成[IsRel] token判断相关性

  3. 基于检索内容生成回答，生成[IsSup] token判断是否有依据

  4. 如不满足条件，触发重新检索或自我修正

效果：比普通RAG幻觉率降低40%。

6.6 Contextual Retrieval

核心思想：Anthropic在2025年提出，在文档分块前先用LLM为每个chunk生成上下文描述。

示例：

加入上下文后的chunk：

效果：

  • 召回失败率降低约49%

  • 配合Reranker可降低67%

  • 显著提升长文档中的细粒度检索精度

6.7 RAG-as-Memory

核心思想：将RAG作为Agent的长期记忆系统。

工作流程：

  1. 每次对话结束后，将关键信息写入知识库

  2. 下次对话时检索历史记忆

  3. 实现真正的"记得你是谁"的个性化交互

技术实现：

  • 记忆分层：短期记忆（对话历史）+ 长期记忆（知识库）

  • 记忆更新：ADD/UPDATE/DELETE/NOOP操作

  • 混合检索：语义搜索 + 图检索 + 时序检索

VikingMem系统：

  • 结构化事件检索用于长期记忆

  • 结合向量检索、图记忆、模块化记忆

  • 在LOCOMO和LongMemEval数据集上验证效果

6.8 覆盖感知检索

核心思想：标准检索器优化的是单个文档的排名，而非确保全面覆盖所有子信息需求。在长文本RAG场景中，覆盖性检索至关重要。

技术方法：

  • nugget-level评估：超越文档级相关性判断，评估事实覆盖度

  • α-nDCG：衡量检索结果的覆盖率和多样性

  • 多查询检索：生成多个查询嵌入以获取多样化视角

  • Maximal Marginal Relevance（MMR）：在相关性和多样性之间平衡

Search for Coverage框架：

  • 学习覆盖感知检索

  • 增强子问题可回答性

  • 通过子问题分解确保全面覆盖

7. 企业级RAG部署方案

7.1 元数据增强RAG

核心思想：使用LLM动态生成有意义的文档片段元数据，提升语义表示和检索精度。

实验结果（3×3实验矩阵）：

  • 递归分块 + TF-IDF加权嵌入：82.5%精度

  • 简单分块 + 前缀融合：NDCG 0.813（最强排序质量）

  • 元数据增强方法始终优于纯内容基线

  • P95延迟保持在30ms以内

实施步骤：

  1. 文档分块（语义分块/递归分块/简单分块）

  2. LLM生成元数据（标题、摘要、关键词、时间戳）

  3. 元数据与内容融合嵌入

  4. 混合检索 + 交叉编码器重排序

7.2 紧凑线索选择（CompSelect）

核心思想：LLM受益于精确、紧凑、结构化的输入，而非完整段落。通过最小充分线索集实现高效推理。

三阶段机制：

  1. 线索提取器：使用包含答案的句子作为微调目标，提取充分潜在线索

  2. 重排序器：基于真实LLM反馈训练，优先排序有效线索

  3. 截断器：使用包含最小充分线索的截断文本作为微调目标，实现高效推理

效果：提升性能的同时降低总延迟和在线延迟，对不可靠检索具有鲁棒性。

7.3 降噪优先检索

核心思想：LLM导向的信息检索应以降噪为首要目标。

降噪技术分类：

  • 选择与剪枝：MMR、DPP、Speculative selection、FILCO

  • 上下文压缩：LLMLingua、LongLLMLingua、RECOMP、Gist Tokens

  • 布局优化：位置校准、拓扑感知重排序、OP-RAG

  • 冲突解决：Chain-of-Note、Astute RAG、ConflictBank

8. 性能评估与优化

8.1 评估指标

8.2 性能优化策略

检索优化：

  • 混合检索（BM25 + Dense）
