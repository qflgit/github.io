Graph RAG 进阶：知识图谱增强的检索生成框架

一、为什么需要 Graph RAG

传统 RAG 依赖向量相似度匹配，在以下场景存在明显短板：

  • 跨文档关联推理："宁德时代供应了哪些车企的电池？"需要连接多个文档中的实体关系，向量检索无法显式建模这种关联

  • 多跳推理："公司 A 的 CEO 毕业于哪个城市的学校？"需要跨越多个实体节点进行路径推理

  • 全局理解："整个语料库的主要风险是什么？"需要对整个文档集合进行主题级综合，而不仅是局部相似匹配

  • 关系型查询："实体 A 与实体 B 之间有什么关联？"向量检索无法直接回答关系路径问题

Graph RAG 通过引入知识图谱（Knowledge Graph）的结构化语义网络，将实体、关系和属性显式建模为图结构，使检索系统不仅能"找得到相关内容"，更能"理解知识之间的内在关联"。

二、知识图谱基础

2.1 什么是知识图谱

知识图谱以（实体，关系，实体）三元组的形式存储结构化知识，本质上是一个有向图：

  • 节点（Node）：实体，如人名、组织、地点、概念、事件、产品等

  • 边（Edge）：关系，如"研发"、"供应"、"投资"、"属于"、"导致"等

  • 属性（Property）：实体的描述信息，如出生日期、成立时间、行业分类等

3.2 阶段一：知识图谱构建

3.2.1 文本分块（Text Chunking）

Graph RAG 建议采用语义分块而非固定长度分块，以保留实体间的上下文关系。实践中常使用较大 chunk size（如 1200 tokens），确保每个片段包含足够的上下文来识别实体间关系。过小的 chunks 会导致跨句关系被切断。

3.2.2 实体与关系抽取（Entity & Relationship Extraction）

这是 Graph RAG 的核心创新。系统使用 LLM（如 GPT-4、Claude、Qwen 等）逐一处理每个 chunk，通过精心设计的提示模板指示模型识别：

  • 实体类型：Person、Organization、Location、Concept、Technology、Event 等

  • 关系类型：研发、供应、投资、合作、属于、导致、影响等

  • 属性信息：描述文本、来源文档、时间戳、置信度等

输出格式通常为三元组列表：

xxxxxxxxxx
[
  {"subject": "宁德时代", "relation": "供应", "object": "蔚来汽车"},
  {"subject": "宁德时代", "relation": "属于", "object": "新能源电池行业"}
]

3.2.3 实体解析与图谱融合（Entity Resolution & Graph Merging）

不同 chunks 中抽取的实体可能以不同名称指向同一实体：

  • "Microsoft"、"微软"、"MSFT" → 同一实体

  • "OpenAI"、"Open AI"、"openai" → 同一实体

实体解析方法：

  • 基于规则的归一化：大小写统一、别名映射表

  • 基于嵌入的聚类：将实体描述编码为向量，计算相似度进行聚类

  • LLM 驱动的消歧：向 LLM 提供候选实体对，让其判断是否指向同一实体

3.2.4 存储与索引

将构建好的知识图谱落地到图数据库：

  • Neo4j：生态成熟，Cypher 查询语言直观

  • NebulaGraph：分布式图数据库，适合大规模场景

  • TigerGraph：支持 GSQL，性能优异

  • Amazon Neptune：云托管，与 AWS 生态集成

索引策略：

  • 实体名称建立全文索引（支持模糊匹配）

  • 实体描述预计算嵌入向量（支持语义相似搜索）

  • 关系类型建立属性索引（支持关系过滤）

四、Microsoft GraphRAG：社区检测与分层摘要

4.1 核心创新

Microsoft GraphRAG 是目前最具影响力的 Graph RAG 开源实现，其核心创新在于社区检测（Community Detection）与分层摘要（Hierarchical Summarization）。

4.2 索引阶段（Indexing Pipeline）

步骤 1：实体与关系抽取

使用 LLM 从文档 chunks 中提取实体和关系三元组，同时为每个实体生成描述文本，并记录来源文档引用。

步骤 2：知识图谱构建

将抽取的三元组构建为图结构，节点存储实体描述和来源引用，边存储关系类型和置信度。

步骤 3：社区检测（Leiden Algorithm）

应用图社区检测算法（如 Leiden 算法）识别紧密关联的实体集群。每个社区代表一个连贯的主题或领域。

社区检测的意义：

  • 将海量实体自动组织为可理解的主题组

  • 为全局查询提供"主题入口"

  • 支持多粒度浏览：从微观实体 → 中观社区 → 宏观主题

步骤 4：社区摘要生成

使用 LLM 为每个社区生成多粒度摘要：

  • L0 级：最细粒度，小社区的详细摘要

  • L1 级：中等粒度，合并相关小社区后的摘要

  • L2 级：最粗粒度，全局主题摘要

这种分层结构使得系统能够回答从"具体事实"到"全局主题"的各类问题。

4.3 查询阶段（Query Pipeline）

GraphRAG 区分两种查询类型：

局部查询（Local Query）

针对特定实体的精确事实查询，如"宁德时代的主要产品是什么？"

  • 检索路径：实体链接 → 向量搜索实体描述 → 召回相关实体节点 → 提取邻域子图

  • 适用场景：精确事实查询、实体属性查询

全局查询（Global Query）

需要对整个语料库进行主题级综合的查询，如"整个文档集合的主要风险是什么？"

  • 检索路径：查询路由 → 选择相关社区层级 → 召回社区摘要 → LLM 综合生成

  • 适用场景：主题分析、趋势总结、跨文档综合

混合查询

许多查询同时使用两种路径：先通过全局查询定位相关主题社区，再通过局部查询深入具体实体细节。

4.4 动态社区选择（Dynamic Community Selection）

最新的 GraphRAG 优化引入了动态社区选择机制：

  • 根据查询语义自动判断应检索哪个层级的社区摘要

  • 避免对所有社区进行全量扫描，显著提升全局查询效率

  • 使用 LLM 作为路由器，将查询映射到最相关的社区子集

五、Graph RAG 的检索策略

5.1 子图检索（Subgraph Retrieval）

从查询中提取关键实体，在图中定位对应节点，然后进行邻域扩展：

xxxxxxxxxx
// 查询公司 A 两跳内的收购路径及目标行业
MATCH (a:Company {name: "A"})-[:ACQUIRED]->(b:Company)-[:IN_INDUSTRY]->(i:Industry)
RETURN a.name AS acquirer, b.name AS target, i.name AS industry
UNION
MATCH (a:Company {name: "A"})-[:ACQUIRED]->(:Company)-[:ACQUIRED]->(b2:Company)-[:IN_INDUSTRY]->(i2:Industry)
RETURN a.name AS acquirer, b2.name AS target, i2.name AS industry

关键参数：

  • 跳数（Hop）：通常 2~3 跳，过深会引入噪声

  • 邻居数量限制：每节点最多返回 N 个邻居

  • 关系类型过滤：只遍历特定类型的关系

  • 置信度阈值：过滤低置信度的边

5.2 路径检索（Path Retrieval）

针对"实体 A 与实体 B 之间有什么关联"类问题，需要发现连接两个实体的路径：

  • 最短路径：使用 BFS 或 Dijkstra 算法找到最短连接路径

  • Top-K 路径：返回多条不同路径，避免遗漏重要关联

  • 路径排序：根据路径长度、边权重、节点重要性综合排序

5.4 混合检索策略

生产环境中，Graph RAG 通常与向量检索结合使用：

xxxxxxxxxx
用户查询
    ├──→ 向量检索路径
    │      └── 语义相似搜索 → 召回相关文本 chunks
    │
    └──→ 图谱检索路径
           ├── 实体提取与链接
           ├── 子图检索（BFS 扩展）
           └── 社区摘要召回（全局查询）
                  ↓
         候选池合并与去重
                  ↓
         融合排序（RRF / 加权融合）
                  ↓
         重排序（Cross-Encoder）
                  ↓
         Top-K 结果送入 LLM

融合要点：

  • 向量检索提供语义细节，图谱检索提供关系结构

  • 两种方式的结果相互验证，降低单一方法的偏差

  • 根据查询类型动态切换主要检索路径

六、进阶框架与技术演进

6.1 HippoRAG：神经生物学启发的长期记忆

HippoRAG 借鉴人脑海马体的记忆机制，将知识图谱与 PageRank 结合：

  • 使用 PPR 算法在 KG 上遍历，为节点分配与查询相关的权重

  • 将文本 chunks 作为段落节点直接嵌入 KG

  • 基于段落节点的 PPR 分数进行文本召回

  • 支持非参数化持续学习，新文档可增量更新图谱而无需重训练

6.2 LightRAG：轻量级双级检索

LightRAG 在 GraphRAG 基础上优化，引入双级索引系统：

  • 低层次索引：以实体为键，绑定相关实体、关系和原文文本

  • 高层次索引：从实体边中抽象出主题概念作为主题键

这种设计使得系统既能回答具体的实体查询，也能处理抽象的主题问题，同时大幅降低索引成本。

6.3 AGRAG：最小成本最大影响子图

AGRAG 提出MCMI（Minimum Cost and Maximum Influence）推理子图概念：

  • 基于统计方法进行实体抽取，降低 LLM 调用成本

  • 根据 KG 结构和输入查询为节点分配权重

  • 生成最小成本且信息覆盖最大的推理子图

  • 为 LLM 提供显式推理链，最大化查询相关信息同时最小化噪声

6.4 Think-on-Graph：深度图推理

Think-on-Graph 让 LLM 直接在知识图谱上进行多步推理：

  • LLM 作为"思考者"，在图上进行 Beam Search 式的探索

  • 每步选择最相关的邻居节点扩展，形成推理路径

  • 支持深度和负责任的推理，可回溯和验证推理步骤

6.5 记忆脑图（Memory Mind Map）

工业实践中，全量构建知识图谱成本高昂且脆弱。"记忆脑图"是一种折中方案：

  • 摒弃盲目全量建图，仅保留对业务场景有差异化价值的要点信息

  • 以根节点（Root Node）和主题节点（Topic Node）为核心骨干

  • 形成轻量化的树状+网状混合结构

  • 为关键路径预计算嵌入，实现"脑图结构 + 向量特征"的双保险

路径描述：

子图摘要：

xxxxxxxxxx
[社区摘要 - L1级]

蔚来汽车（下游客户）等。关键关系为"供应"和"合作研发"。

7.2 提示工程要点

  • 明确要求引用图证据：在提示中要求模型基于提供的三元组和路径进行回答

  • 来源追溯：要求模型标注每条信息的来源文档和路径

  • 结构化输出：对敏感领域（财务、医疗）使用模板化输出和字段校验

  • 证据融合：同时提供"结构化三元组/路径"和"原文片段"，兼顾事实性与文本细节

7.3 幻觉控制

  • 结构化约束：知识图谱提供显式的事实边界，减少模型自由发挥空间

  • 路径验证：要求模型的推理步骤必须与图谱中的路径一致

  • 置信度过滤：只使用高置信度的三元组作为证据

  • 多源交叉验证：同一事实在多个文档中出现时可信度更高

八、Graph RAG 的适用场景与局限

8.1 最佳适用场景

8.2 局限与注意事项

  • 索引成本高：构建知识图谱需要大量 LLM 调用，索引阶段成本显著高于传统 RAG

  • 实体抽取质量：开放域实体抽取存在歧义和错误，需要质量控制机制

  • 图谱维护：文档更新时需要增量更新图谱，维护复杂度高于向量库

  • 并非万能：对于简单的事实查询，传统向量 RAG 可能更轻量高效

  • 规模权衡：小规模文档集（<1000 篇）的 Graph RAG 收益可能不抵开销

8.3 何时使用 Graph RAG

根据研究分析，Graph RAG 在以下条件下表现最优：

  • 语料库规模较大（>1000 篇文档）

  • 查询需要跨文档关联或多跳推理

  • 领域具有清晰的实体类型和关系模式

  • 可接受较高的索引时间和计算成本

  • 对可解释性和溯源有强需求

9.2 渐进式落地路径

阶段 1：轻量起步

  • 使用 LLM 从核心文档中抽取高频实体和关键关系

  • 构建小规模知识图谱（<1万实体）

  • 引入实体解析和图谱融合机制

  • 引入图神经网络（GNN）增强节点表示

  • 实现动态社区选择和自适应检索

  • 建立完整的质量监控和反馈闭环

十、总结

Graph RAG 代表了 RAG 技术从"语义匹配"向"结构推理"的重要演进。其核心优势在于：

  1. 显式关系建模：通过知识图谱将实体间的关联显式化，突破向量检索的语义黑盒

  2. 多跳推理能力：图遍历天然支持跨实体、跨文档的复杂推理链

  3. 全局理解：社区检测和分层摘要使系统能够回答需要整体视角的全局性问题

  4. 可解释性：推理路径可追溯、可验证，满足高可信场景需求

从 Microsoft GraphRAG 的社区检测到 HippoRAG 的神经记忆机制，从 LightRAG 的双级索引到 AGRAG 的成本优化，Graph RAG 的技术生态正在快速成熟。在实际落地中，建议采用渐进式策略：从轻量级图谱起步，与向量检索形成互补，逐步扩展至完整的 Graph RAG 体系。

Graph RAG 不是对传统 RAG 的替代，而是对其能力的结构性增强——在需要关系推理和全局理解的场景中，知识图谱提供了向量空间无法替代的结构化智力。
