1. 什么是 AI Skill

AI Skill 是一组结构化的指令、脚本和资源文件，用于扩展 AI Agent（如 Claude Code、Kimi、OpenClaw 等）的能力。Skill 本质上是一个文件夹，其中包含：

  • SKILL.md：核心指令文件，包含 YAML 元数据和 Markdown 指令内容

  • scripts/（可选）：可执行脚本（Python、Bash、JavaScript 等）

  • references/（可选）：补充文档和参考资料

  • assets/（可选）：模板、图片、数据文件等静态资源

Skill 让 AI Agent 能够以可重复、可复用的方式完成特定任务，例如：代码审查、文档生成、数据分析、API 测试等。

2. Skill 的核心结构

2.1 目录结构

一个标准的 Skill 目录结构如下：

my-awesome-skill/
├── SKILL.md              # 必需：元数据 + 指令
├── scripts/              # 可选：可执行代码
│   └── analyze.py
├── references/           # 可选：补充文档
│   └── REFERENCE.md
├── assets/               # 可选：静态资源
│   └── template.json
└── README.md             # 可选：面向人类的说明文档

### 3.4 步骤四：编写辅助脚本


**scripts/run_api_tests.py**：


```python
#!/usr/bin/env python3
# API Test Runner - Executes tests from a JSON specification file.


import json
import sys
import argparse
import requests
from datetime import datetime


def run_test(endpoint, test_case, base_url):
    # Execute a single API test case.
    url = f"{base_url}{endpoint['path'].format(**test_case.get('params', {}))}"
    method = endpoint['method']
    headers = endpoint.get('headers', {})
    body = test_case.get('body')


    start_time = datetime.now()
    try:
        response = requests.request(method, url, headers=headers, json=body, timeout=30)
        duration = (datetime.now() - start_time).total_seconds() * 1000


        result = {
            "name": test_case['name'],
            "status": "PASS",
            "duration_ms": round(duration, 2),
            "actual_status": response.status_code,
            "expected_status": test_case.get('expected_status', 200)
        }


        if response.status_code != test_case.get('expected_status', 200):
            result['status'] = 'FAIL'
            result['error'] = f"Status mismatch: expected {test_case.get('expected_status', 200)}, got {response.status_code}"


        return result
    except Exception as e:
        return {
            "name": test_case['name'],
            "status": "ERROR",
            "error": str(e)
        }


def main():
    parser = argparse.ArgumentParser(description='Run API tests from specification')
    parser.add_argument('--spec', required=True, help='Path to test specification JSON')
    args = parser.parse_args()


    with open(args.spec) as f:
        spec = json.load(f)


    results = []
    for endpoint in spec['endpoints']:
        for test in endpoint['tests']:
            result = run_test(endpoint, test, spec['base_url'])
            results.append(result)


    # Output JSON report
    print(json.dumps({"results": results, "summary": {
        "total": len(results),
        "passed": sum(1 for r in results if r['status'] == 'PASS'),
        "failed": sum(1 for r in results if r['status'] in ('FAIL', 'ERROR'))
    }}, indent=2))


if __name__ == '__main__':
    main()

5.2 提交到商业市场（如 Agensi）

商业市场通常有更严格的审核流程：

  1. 注册开发者账号：在 marketplace 平台注册并验证身份

  2. 准备提交材料：

    • 完整的 SKILL.md（遵循平台的 frontmatter 规范）

    • 演示视频或截图

    • 定价信息（如果是付费 Skill）

  3. 安全扫描：平台会自动进行 8 点安全检查：

    • 文件结构验证

    • 危险命令模式检测

    • 密钥/密码泄露扫描

    • 环境变量采集检测

    • 网络访问审计

    • 代码混淆检测

    • 提示注入筛查

  4. 人工审核：通过自动扫描后进入人工审核阶段

  5. 上架发布：审核通过后 Skill 出现在市场中

7. Skill 质量优化建议

7.1 渐进式披露设计

Agent 会渐进式加载 Skill 内容，因此应合理组织信息层级：

建议：

  • 主 SKILL.md 控制在 500 行以内

  • 详细参考资料放入 references/ 目录

  • 脚本保持独立且文档齐全

7.2 描述优化

description 字段是 Skill 被发现的唯一依据，应包含：

  • 功能描述：这个 Skill 能做什么

  • 触发关键词：帮助 Agent 识别何时使用该 Skill

  • 使用场景：具体的使用示例

好的描述：

xxxxxxxxxx
description: Extracts text and tables from PDF files, fills PDF forms, and merges multiple PDFs. Use when working with PDF documents or when the user mentions PDFs, forms, or document extraction.

差的描述：

xxxxxxxxxx
description: Helps with PDFs.

8. 常见问题与排错

8.1 Skill 无法被识别

症状：提到 Skill 名称后 Agent 没有加载该 Skill

排查步骤：

  1. 检查 name 字段是否与目录名完全一致

  2. 确认 SKILL.md 位于 Skill 根目录（不是子目录）

  3. 验证 YAML frontmatter 格式正确（--- 分隔符）

  4. 检查 description 是否包含相关关键词

8.2 安装后无法调用

症状：/plugin install 成功但 Skill 不生效

解决方案：

xxxxxxxxxx
# 1. 检查安装路径
ls ~/.claude/skills/api-test-assistant/SKILL.md

8.3 Frontmatter 验证失败

常见错误：

  • name 包含大写字母 -> 改为全小写

  • name 以连字符开头或结尾 -> 移除首尾连字符

  • description 超过 1024 字符 -> 精简描述

  • name 与目录名不匹配 -> 统一名称

8.5 跨平台兼容性

  • 避免使用平台特定的路径分隔符（使用 / 而非 Windows 反斜杠）

  • 脚本优先使用 Python（跨平台）而非 Bash（仅限 Unix）

  • 在 compatibility 字段中明确说明系统要求
