Skills 详解：建造、工作流程、特点及与 MCP 的对比

一句话定义

Skills = 可复用的 AI 工作流定义，以文件形式（如 SKILL.md）封装领域知识、操作步骤和可执行脚本，让 AI Agent 在特定场景下按预设流程自主完成任务。与 MCP（Model Context Protocol）不同，Skills 关注"如何做"（How），MCP 关注"连接什么"（What）。

# Deploy Webapp Skill


## 目标
将前端项目部署到主流云平台，并配置自动 CI/CD 流水线。


## 前置条件
- 项目已初始化 npm/yarn/pnpm
- 存在 package.json 且包含 build 脚本
- 已配置 git 仓库


## 执行步骤


### 1. 分析项目结构
检查项目类型（React/Vue/Next.js/Svelte）：
```bash
# 读取 package.json 依赖
cat package.json | grep -E "next|react|vue|svelte"

2. 选择部署平台

根据项目特征选择最优平台：

  • Next.js → Vercel（首选）或 Netlify

  • React SPA → Netlify 或 Cloudflare Pages

  • Vue/Nuxt → Netlify 或 Vercel

  • 静态站点 → Cloudflare Pages（最快）

3. 配置部署文件

Vercel (vercel.json)

xxxxxxxxxx
{
  "version": 2,
  "builds": [{ "src": "package.json", "use": "@vercel/next" }],
  "routes": [{ "src": "/(.*)", "dest": "/index.html" }]
}

Netlify (netlify.toml)

xxxxxxxxxx
[build]
  command = "npm run build"
  publish = "dist"


[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200

4. 设置 CI/CD

GitHub Actions (.github/workflows/deploy.yml)

xxxxxxxxxx
name: Deploy
on: [push]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: npm ci && npm run build
      - run: npx vercel --prod --token=${{ secrets.VERCEL_TOKEN }}

5. 验证部署

  • 检查构建日志无错误

  • 验证所有路由可访问

  • 确认 HTTPS 证书生效

  • 测试 Lighthouse 性能分数 > 90

输出格式

部署完成后返回：

  • 生产环境 URL

  • 预览环境 URL（如适用）

  • 构建状态徽章 Markdown

  • 性能评分摘要

Skills 的工作流程

完整生命周期

xxxxxxxxxx
┌─────────────────────────────────────────────────────────────┐
│  1. 发现阶段 (Discovery)                                     │
│     └── Agent 启动时扫描 skills 目录                          │
│     └── 只加载 name + description（元数据，不占上下文）        │
├─────────────────────────────────────────────────────────────┤
│  2. 匹配阶段 (Matching)                                      │
│     └── 用户输入任务描述                                       │
│     └── Agent 评估哪个 skill 最相关（语义匹配）                │
│     └── 示例："部署网站" → 匹配 deploy-webapp skill          │
├─────────────────────────────────────────────────────────────┤
│  3. 加载阶段 (Loading)                                       │
│     └── 将完整 SKILL.md 内容注入 Agent 上下文                  │
│     └── 包含：指令、模板、脚本、示例                            │
│     └── 上下文成本：中等（通常 1K-5K tokens）                 │
├─────────────────────────────────────────────────────────────┤
│  4. 执行阶段 (Execution)                                     │
│     └── Agent 按 SKILL.md 步骤逐步执行                        │
│     └── 调用工具（MCP / 本地脚本 / 系统命令）                  │
│     └── 每步可请求用户确认（人机协作模式）                      │
├─────────────────────────────────────────────────────────────┤
│  5. 反馈阶段 (Feedback)                                      │
│     └── 输出结果按 SKILL.md 定义的格式呈现                     │
│     └── 记录执行日志，用于后续优化                              │
└─────────────────────────────────────────────────────────────┘

Skills 的核心特点

1. 渐进式披露（Progressive Disclosure）

优势：可安装数十个 skills 而不膨胀上下文窗口。

2. 可执行性（Executability）

xxxxxxxxxx
# SKILL.md 中的可执行代码块
---
name: database-migration
---


## 执行脚本


```bash
#!/bin/bash
# @skill-script: migrate.sh


# 自动执行数据库迁移
npx prisma migrate dev --name $(date +%Y%m%d_%H%M%S)
npx prisma generate

Agent 可直接执行 migrate.sh，无需用户手动操作。

3. 上下文隔离（Context Fork）

xxxxxxxxxx
# 在 skill 中指定执行模式
---
metadata:
  execution: fork    # 在子 Agent 中执行，隔离上下文
---


# 效果：
# - 主会话上下文保持干净
# - skill 执行中的中间结果不污染主会话
# - 失败时不影响主会话状态

1. 设计原则

一句话总结

Skills 是 AI Agent 的"操作手册"——将领域知识、操作流程和可执行脚本封装为文件，实现渐进式加载和按需执行；MCP 是 AI Agent 的"USB 接口"——标准化连接外部工具和数据。两者不是竞争关系，而是互补的架构层：Skills 解决"How"（如何做事），MCP 解决"What"（能连什么），最佳实践是 Skills 编排流程 + MCP 获取实时数据，共同构建完整的 Agent 能力栈。
