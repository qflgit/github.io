## 1. 概述

深度学习模型推理的性能优化主要依赖两大技术方向：**量化**（Quantization）和**编译优化**（Compiler Optimization）。量化通过降低模型权重和激活值的精度来减少内存占用和计算量；编译优化则通过静态分析、图变换和代码生成，将高级模型描述转换为针对特定硬件高度优化的机器代码。

当前AI硬件环境极度碎片化：训练端有NVIDIA A100/H100/H200、AMD MI300X、Google TPU v5等；边端有Apple M4 Neural Engine、Qualcomm Hexagon DSP、Intel NPU、NVIDIA Jetson等。如果没有编译器抽象层，每个模型需要为每种硬件手写优化代码，这是不可能完成的任务。AI编译器的核心价值在于：**通过静态分析和全局优化，自动生成比手写更快的代码**。

## 2. 量化技术

### 2.1 量化基础概念

量化是将模型从高精度（如FP32、FP16）转换为低精度（如INT8、FP8、INT4）表示的技术。其核心价值包括：
- **减少内存占用**：INT8相比FP32模型大小减少75%
- **提高计算效率**：低精度运算更快，硬件利用率更高
- **降低功耗**：数据传输和计算能耗显著下降
- **提升吞吐量**：相同硬件可处理更大批量

### 2.2 训练后量化（PTQ）

**原理**：对已经训练好的浮点模型，使用小批量校准数据（Calibration）统计激活值的分布，计算缩放因子（Scaling Factor），将权重和激活值映射到低精度表示。

**流程**：
1. 准备浮点模型和校准数据集（通常512条数据即可）
2. 统计每层激活值的max/min或分布
3. 计算per-tensor或per-channel的缩放因子
4. 将FP32/FP16权重和激活值量化为低精度
5. 验证精度损失，必要时调整量化策略

**优点**：
- 无需重新训练，部署速度快
- 校准时间仅需分钟级
- 适合快速上线场景

**缺点**：
- 精度损失相对较大
- 对异常值（outlier）敏感
- 某些模型量化后精度下降明显

### 2.3 量化感知训练（QAT）

**原理**：在训练过程中插入伪量化（FakeQuantize）算子，模拟量化和反量化过程，让模型在训练时就适应低精度表示。

**流程**：
1. 在浮点模型中插入QDQ（Quantize/Dequantize）节点
2. 前向传播时模拟量化效果
3. 反向传播时计算梯度（通常使用直通估计器STE）
4. 模型收敛后导出量化模型

**优点**：
- 精度保持最佳
- 模型对量化误差有补偿能力
- 适合对精度要求高的场景

**缺点**：
- 需要重新训练，耗时较长
- 训练过程更复杂
- 需要更多工程投入

### 2.4 主流量化方案对比

| 量化方法 | 权重精度 | 激活精度 | 性能提升 | 精度影响 | 校准时间 | 适用场景 |
|---------|---------|---------|---------|---------|---------|---------|
| FP8 (W8A8) | FP8 | FP8 | 中等 | 非常低 | 分钟 | H100/H200+ |
| INT8 SQ (W8A8) | INT8 | INT8 | 中等 | 中等 | 分钟 | 通用GPU |
| INT8 Weight-only (W8A16) | INT8 | FP16 | 中等 | 低 | 不需要 | 快速部署 |
| INT4 Weight-only (W4A16) | INT4 | FP16 | 高 | 高 | 不需要 | 极致压缩 |
| INT4 AWQ (W4A16) | INT4 | FP16 | 高 | 低 | 数十分钟 | 通用部署 |
| INT4 GPTQ | INT4 | FP16 | 高 | 低 | 数十分钟 | 通用部署 |
| INT4-FP8 AWQ (W4A8) | INT4 | FP8 | 高 | 低 | 数十分钟 | 极致性能 |

### 2.5 FP8量化

FP8（8位浮点数）是近年来最受关注的量化格式，有两种数据类型：
- **E4M3**：4位指数+3位尾数，动态范围约±448
- **E5M2**：5位指数+2位尾数，动态范围更大

**优势**：
- 相比INT8，FP8能更好地保持模型精度（动态范围自适应）
- 相比FP16，计算效率显著提升
- 特别适合LLM长上下文生成与多模态融合任务
- H100/H200原生支持FP8 Tensor Core

**实测数据（Llama-3-70B，A100-80GB）**：

| 量化格式 | 吞吐(tokens/s) | KV缓存显存(GB) | BLEU-4下降 |
|---------|--------------|---------------|-----------|
| INT8 + KV Cache quant | 142 | 18.3 | -1.9 |
| FP8-E4M3 + dynamic KV | 187 | 11.6 | -0.7 |

**TensorRT-LLM FP8性能数据（Llama-2-7B，H100）**：

| 指标 | FP16 | FP8 | 提升幅度 |
|-----|------|-----|---------|
| Token吞吐(tokens/s) | 2474 | 6049 | +144% |
| 请求吞吐(req/s) | 1.21 | 2.95 | +144% |
| 首token延迟(ms) | 147.6 | 88.0 | -40% |

**FP8 vs INT8选择建议**：
- 拥有NVIDIA H100/H200或AMD MI300X集群，追求极致吞吐 → 选FP8
- 模型激活值动态范围适中，可安全压缩至8位浮点 → 选FP8
- 团队具备底层调优能力 → 选FP8
- 需避免INT8复杂的校准流程与离群值处理 → 选FP8
- 在MX格式（block size=32）下，MXINT8在全部12个大模型（0.6B-235B）中均优于MXFP8，硬件层面能耗降低37%、芯片面积减少34%

### 2.6 混合精度量化

**原理**：不同层使用不同精度，对精度敏感的层保持高精度，对精度不敏感的层使用低精度。

**策略**：
- **W8A8 + FP16 Attention**：Attention层保持FP16，其余W8A8
- **W4A16 + FP8 KV Cache**：权重INT4，激活FP16，KV Cache FP8
- **动态精度切换**：根据输入动态选择精度

## 3. 编译器优化技术

### 3.1 计算图优化

**常量折叠（Constant Folding）**：在编译时预先计算常量表达式，减少运行时计算。

**死代码消除（Dead Code Elimination）**：移除不影响输出的计算节点。

**公共子表达式消除（CSE）**：识别并复用重复计算。

**布局转换（Layout Transformation）**：NCHW↔NHWC等数据布局优化，匹配硬件偏好。

### 3.2 算子融合

算子融合是编译优化中最重要的技术之一，其核心价值在于减少内存访问和kernel启动开销。

**不融合的Attention计算**：
```
Q = Linear(x) → GPU kernel 1 → 显存
K = Linear(x) → GPU kernel 2 → 显存
V = Linear(x) → GPU kernel 3 → 显存
QK = Q @ K.T → GPU kernel 4 → 显存
Scores = Softmax(QK) → GPU kernel 5 → 显存
Out = Scores @ V → GPU kernel 6 → 显存
```
问题：6次显存读写，6次GPU kernel启动

**融合后（FlashAttention核心思想）**：
```
→ 单个GPU kernel完成整个Attention计算
→ 中间结果保留在SRAM（快）而非显存（慢）
→ 显存读写量减少5-10x
→ 延迟降低2-4x
```

**融合类型**：
- **垂直融合**：Conv2D + BatchNorm + ReLU → 单个kernel
- **水平融合**：多个独立Conv2D → 单个kernel
- **输入融合**：共享输入的多个算子合并

**实测效果**：
- TVM AutoTensorization将Conv2D+ReLU访存次数降低67%（NVIDIA A100实测）
- 算子融合可使延迟降低15-40%

### 3.3 内存优化

**内存重用分析**：识别计算图中的临时缓冲区复用机会，减少内存分配。

**内存布局优化**：根据硬件特性调整张量数据布局，最小化内存访问开销。

**预取策略**：实现数据预加载以隐藏内存访问延迟。

**内存合并（Memory Coalescing）**：确保线程以连续方式访问内存，最大化带宽利用率。

### 3.4 循环优化

**循环分块（Loop Tiling/Blocking）**：将大循环分解为小块，提升缓存利用率。例如32x32的块大小对应4KB缓存区域，匹配L1缓存大小。

**循环展开（Loop Unrolling）**：减少循环控制开销，增加指令级并行。

**循环置换（Loop Permutation）**：改变嵌套循环顺序，优化数据访问模式。

**向量化（Vectorization）**：利用SIMD指令（如AVX-512、NEON）一次处理多个数据元素。

**并行化（Parallelization）**：利用多核CPU或GPU多线程并行执行。

**TVM矩阵乘法优化实测**：

| 优化策略 | 执行时间 | 相对基线 |
|---------|---------|---------|
| 无优化（naive） | 2.233s | 1.0x |
| 分块（blocking） | 0.249s | 0.11x（9x加速） |
| 向量化（vectorization） | 0.257s | 0.12x |
| 循环置换（loop permutation） | 0.130s | 0.058x（17x加速） |
| 数组打包（array packing） | 0.140s | 0.063x |
| 块缓存（block caching） | 0.132s | 0.059x |
| 并行化（parallelization） | 0.026s | 0.012x（84x加速） |

### 3.5 自动调度

**AutoTVM**：基于模板的自动调优，为每个算子搜索最优调度参数。

**Meta-Schedule**：引入代价模型引导的进化搜索，对BERT-Large的编译时间从8.6小时缩短至15分钟。

**基于GNN的调度策略**：ASPLOS'23研究显示，基于GNN的调度策略生成器可将搜索效率提升19倍。

## 4. TensorRT

### 4.1 架构与原理

TensorRT是NVIDIA推出的高性能推理引擎，基于CUDA并行编程模型构建，包含用于优化神经网络模型的库。其核心优化技术包括：
- **量化**：支持FP8、FP4、INT8、INT4等低精度格式
- **层和张量融合**：将多个算子合并为单个kernel
- **内核调优**：针对特定GPU架构选择最优kernel实现
- **动态张量内存**：运行时内存分配优化
- **多流执行**：并行处理多个推理请求
- **时间融合**：针对循环网络的优化

TensorRT相比仅使用CPU的平台，推理速度可提高36倍。

### 4.2 量化支持

TensorRT支持两种量化模式：

**隐式量化**：TensorRT自动决定量化位置，可能添加额外的转换以提升性能。

**显式量化（Q/DQ）**：量化和反量化操作明确表示为QuantizeLayer和DequantizeLayer节点。优化器仅执行由模型语义决定的量化类型转换。推荐配置：
- 激活使用per-tensor量化
- 权重使用per-channel量化
- 此配置经验证可获得最佳量化精度

### 4.3 TensorRT-LLM

TensorRT-LLM是NVIDIA专为LLM推理优化的框架，提供Python API用于定义大语言模型并构建TensorRT引擎。

**核心优化技术**：

**1. 量化**
支持多种精度格式：W8A8 SQ（SmoothQuant）、W4A16/W8A16、W4A16 AWQ、W4A16 GPTQ、FP8等。

**2. In-Flight Batching（Continuous Batching）**
传统Static Batching需要等批次中所有序列推理完成后才能进行下一次批次，存在资源浪费。In-Flight Batching允许在序列处理完成后立即插入新序列，提升资源利用率。

**3. Attention优化**
- MHA（Multi-head Attention）：标准多头注意力
- MQA（Multi-query Attention）：所有query共享一份KV，减少显存
- GQA（Group-query Attention）：query分组共享KV，平衡性能和精度
- FP8 FMHA：首token计算优化，输入序列越大加速越明显

**4. KV Cache量化**
- FP8 KV Cache：显存减半，吞吐量提升约56%
- 从FP16 KV Cache切换到FP8，可在H100上运行2-3倍大的批量

**性能数据**：

| 模型 | 批量大小 | FP8 vs FP16加速 | INT8 SQ vs FP16加速 |
|-----|---------|----------------|-------------------|
| GPT-J | 1 | 1.40x | 1.40x |
| GPT-J | 8 | 1.44x | 1.30x |
| LLaMA-v2-7B | 1 | 1.51x | 1.47x |
| LLaMA-v2-7B | 8 | 1.40x | 1.32x |

**高级优化配置**：
```python
# KV缓存量化
quant_config = QuantConfig(
    quant_algo=QuantAlgo.FP8,
    kv_cache_quant_algo=QuantAlgo.FP8
)

# Reduce Norm融合
build_config.plugin_config.reduce_fusion = True
build_config.plugin_config.user_buffer = True

# GEMM + SwiGLU融合
build_config.plugin_config.gemm_swiglu_plugin = 'fp8'

# 低延迟GEMM
build_config.plugin_config.low_latency_gemm_plugin = 'fp8'
```

### 4.4 TensorRT Model Optimizer

TensorRT Model Optimizer（原AMMO）是一个库，包含最先进的模型优化技术：
- 基于原始精度的模拟量化
- 在模型精度和不同低精度格式之间找到最佳平衡
- 支持PyTorch和ONNX框架中的量化
- 可将具有模拟量化的模型导出到TensorRT或TensorRT-LLM部署

**使用流程**：


## 5. TVM

### 5.1 架构概述

TVM（Tensor Virtual Machine）是陈天奇团队在2018年发布的开源深度学习编译器，目标是自动优化任意深度学习模型在任意硬件上的性能。

**TVM编译流程**：
```
深度学习模型（PyTorch/ONNX/TF）
    ↓
[Relay IR：图级别优化]
    - 算子融合
    - 常量折叠
    - 死代码消除
    - 类型推断
    ↓
[TE（Tensor Expression）：算子级别优化]
    - 描述算子的计算逻辑
    - 独立于调度策略（"做什么"和"怎么做"分离）
    ↓
[TIR（Tensor Intermediate Representation）：硬件优化]
    - 循环优化
    - 内存分配
    - 向量化/并行化
    ↓
[代码生成]
    - CUDA/ROCm（GPU）
    - LLVM（CPU/ARM）
    - Metal（Apple Silicon）
    - Hexagon（Qualcomm DSP）
    - Vulkan（通用GPU）
```

### 5.2 Relay IR与计算图优化

Relay是TVM的高级中间表示，支持：
- 自动类型推断
- 控制流（if-then-else、循环）
- 递归函数
- 图级别优化（算子融合、常量折叠等）

**TVM Unity（最新版本）**：
- **Relax Virtual Machine**：支持动态控制流编译，在Transformer可变长序列场景下，相比PyTorch Eager模式减少83%的显存碎片
- 统一动态静态编译
- 支持动态shape模型优化

### 5.3 Tensor Expression（TE）

TE是TVM的核心组件，实现了计算与调度的分离：

**计算描述（"做什么"）**：
```python
k = te.reduce_axis((0, K), "k")
A = te.placeholder((M, K), name="A")
B = te.placeholder((K, N), name="B")
C = te.compute((M, N), lambda x, y: te.sum(A[x, k] * B[k, y], axis=k), name="C")
```

**调度描述（"怎么做"）**：
```python
s = te.create_schedule(C.op)
# 分块
xo, yo, xi, yi = s[C].tile(C.op.axis[0], C.op.axis[1], bn, bn)
# 分割归约轴
ko, ki = s[C].split(k, factor=4)
# 重排序
s[C].reorder(xo, yo, ko, xi, ki, yi)
# 向量化
s[C].vectorize(yi)
# 并行化
s[C].parallel(xo)
```

### 5.4 TensorIR

TensorIR是TVM的新一代张量程序优化抽象，核心创新：

**Block结构**：划分张量程序，与外部嵌套循环隔离，有效表示张量化计算。

**变换原语**：生成丰富的张量化程序搜索空间，并有正确性验证。

**张量化感知自动调度器**：自动为给定平台生成高性能程序。

**虚拟张量指令集**：通过指令级联（Tensor Intrin）在AMD MI250X上实现FP8矩阵乘吞吐量达到理论峰值92%。

**性能提升**：与现有机器学习编译方法相比，TensorIR最高可实现7倍加速。

### 5.5 AutoTVM与Meta-Schedule

**AutoTVM**：
- 基于模板的自动调优
- 使用XGBoost等机器学习模型预测最优配置
- 需要为每个算子定义搜索模板

**Meta-Schedule**：
- 引入代价模型引导的进化搜索
- 无需手动编写模板
- BERT-Large编译时间从8.6小时缩短至15分钟
- 支持跨工作负载的调度迁移

**自动调优流程**：
```python
from tvm.autotvm.tuner import XGBTuner
from tvm import autotvm

# 提取调优任务
tasks = autotvm.task.extract_from_program(mod["main"], target=target, params=params)

# 对每个算子自动搜索最优调度
for task in tasks:
    tuner = XGBTuner(task)
    tuner.tune(
        n_trial=1000,
        early_stopping=600,
        measure_option=autotvm.measure_option(
            builder=autotvm.LocalBuilder(),
            runner=autotvm.LocalRunner(repeat=3),
        ),
    )

# 使用调优结果编译
with autotvm.apply_history_best("tuning_records.json"):
    with tvm.transform.PassContext(opt_level=3):
        lib = relay.build(mod, target=target, params=params)
```

## 6. MLIR

### 6.1 设计哲学

MLIR（Multi-Level Intermediate Representation）是Google在2019年开源的编译器基础设施，LLVM项目的一部分。其核心设计理念是**可扩展的多层次IR**。

**解决的问题**：
- 软件碎片化：每个硬件平台、每个框架都有自己的"方言"
- 编译技术栈冗余：大量优化工作在各工具链中重复实现
- 沟通成本极高：模型部署到多种设备需要多次转换

**MLIR的核心思想**：不是创造一种"终极IR"来取代所有，而是设计一个**元框架**，允许不同的"方言"（Dialect）在其中共存、交互和转换。

### 6.2 Dialect体系

MLIR通过Dialect实现多层次抽象：

```
Python/TensorFlow/PyTorch
    ↓
[TensorFlow Dialect] / [Torch Dialect]
    ↓ lowering（降层）
[MHLO / StableHLO Dialect] ← 硬件无关的高层线性代数操作
    ↓ lowering
[Linalg Dialect] ← 结构化计算，便于优化分析
    ↓ lowering
[Vector Dialect] ← SIMD向量操作
    ↓ lowering
[LLVM Dialect] ← LLVM IR等价
    ↓
[目标硬件：x86/ARM/CUDA/Metal]
```

**核心Dialect**：
- **Linalg Dialect**：结构化操作抽象，将计算语义与硬件实现分离，使卷积算子在不同加速器上的代码生成效率提升3-7倍
- **Affine Dialect**：基于多面体模型的循环优化
- **GPU Dialect**：GPU编程抽象
- **SPIR-V Dialect**：Vulkan/OpenCL代码生成

### 6.3 Pass管道与优化

MLIR的优化过程由一系列Pass组成：

```
输入MLIR（高层语义）
    ↓
[Canonicalizer] 规范化
    ↓
[Inliner] 内联函数
    ↓
[GNN Passes] 图神经网络特定优化
    ↓
[Linalg on Tensors] 降维
    ↓
[Tiling & Fusion] 分块与融合
    ↓
[Host Passes] Host侧代码生成
[Device Passes] Device侧代码生成
```

**关键优化**：
- **算子融合**：将多个逐元素操作合并为一个kernel（如ReLU + Scale → 单个kernel）
- **布局优化**：选择最优的张量内存布局（NHWC vs NCHW），最小化内存访问开销
- **循环优化**：循环平铺（提升缓存利用率）、循环展开（减少控制开销）、向量化（利用SIMD指令）
- **内存优化**：张量重计算vs缓存、内存合并

**MLIR的Linalg Dialect实现跨层级的Tile尺寸自动推导，在ResNet-50上获得1.3倍加速。**

### 6.4 IREE编译器

IREE（Intermediate Representation Execution Environment）是基于MLIR的端到端编译器，特点：
- 支持多芯片全连接
- Google TPU v4上实现吞吐量达2.1 PetaFLOPS
- 编译速度快（ResNet-50仅需420秒，vs TVM的1850秒）
- 但性能略低于TVM和TensorRT

### 6.5 与TVM的关系

| 维度 | TVM | MLIR |
|-----|-----|------|
| 设计目标 | 端到端深度学习编译 | 通用多层IR基础设施 |
| 核心抽象 | 计算/调度分离 | 方言/操作/区域 |
| 优化方法 | 自动调度搜索+图优化 | 模式重写+多级转换 |
| 硬件支持 | 重点支持AI加速器 | 全栈硬件（CPU/GPU/FPGA等） |
| 社区生态 | 深度学习编译器社区 | LLVM生态扩展 |
| 学习曲线 | 中等（需理解调度） | 较陡（需理解多层IR） |

**实际关系**：TVM正在逐步集成MLIR，利用MLIR的Dialect系统扩展其表示能力。

## 7. TileIR

### 7.1 背景与动机

TileIR（Tile Intermediate Representation）是面向GPU Tile编程的新型中间表示，与2026年GPU编程范式变革密切相关。

**传统GPU编程的问题**：
- CUDA kernel手写优化门槛高
- 不同GPU架构（Ampere、Hopper、Blackwell）的指令集差异大
- 代码难以跨版本兼容
- 深度学习从业者需要同时掌握算法和底层GPU优化

**Tile编程的核心思想**：
- 将计算分解为固定大小的"Tile"（块）
- 自动优化内存访问和硬件资源分配
- 开发者像使用NumPy一样编写高性能GPU代码

### 7.2 核心概念

**Tile IR虚拟指令集**：
- 抽象了不同GPU架构的共性
- 将Triton易用的分块编程模型直接编译到CUDA Tile IR
- 对深度学习从业者和GPU开发者来说，能同时获得高性能、跨版本兼容和面向未来的能力

**自动优化能力**：
- 自动优化内存访问模式
- 自动分配硬件资源（寄存器、共享内存）
- 自动生成最优的warp级调度

**关键特性**：
- 分块（Tiling）：将大矩阵分解为适合SRAM的小块
- 共享内存管理：自动规划数据在共享内存中的布局
- 同步指令优化：最小化线程同步开销
- 寄存器分配：自动优化寄存器使用

### 7.3 与TVM TensorIR的关系

| 特性 | TVM TensorIR | TileIR |
|-----|-------------|--------|
| 目标 | 通用张量程序优化 | GPU Tile编程优化 |
| 抽象层次 | 高（接近算法描述） | 中（接近硬件执行） |
| 自动调度 | 是（AutoTVM/Meta-Schedule） | 是（编译器自动优化） |
| 跨架构 | CPU/GPU/DSP/FPGA | 主要面向GPU |
| 用户接口 | Python DSL | 类似NumPy的API |
| 与Triton关系 | 可集成 | Triton编译目标之一 |

**实际关系**：TileIR可以视为TensorIR在GPU领域的特化，两者都追求"计算与调度分离"的设计理念。Triton的编译后端可以生成Tile IR，然后进一步编译为具体的GPU机器码。

### 7.4 应用场景

- **矩阵乘法**：GEMM的Tile分解是经典应用
- **卷积运算**：将卷积转换为im2col + GEMM的Tile优化
- **Attention机制**：FlashAttention的分块计算天然适合TileIR
- **Transformer推理**：长序列的KV Cache分块处理

## 8. 其他编译器与工具

### 8.1 torch.compile

PyTorch 2.0引入的编译优化工具，将编译优化带给普通开发者。

**核心组件**：
- **TorchDynamo**：通过Python字节码解析实现99%算子捕获率，在可变分支结构中保持图完整性
- **TorchInductor**：默认编译后端，生成优化的C++/Triton代码
- **AOTAutograd**：提前自动微分，优化反向传播

**使用方式**：
```python
import torch

# 一行代码启用编译优化
model = torch.compile(model, mode="max-autotune")

# 模式选择
# "default"：平衡编译时间和性能
# "reduce-overhead"：减少编译开销
# "max-autotune"：最大性能，编译时间最长
```

**性能提升**：1.5-2x，工程成本极低（一行代码）

### 8.2 XLA

Google推出的高性能机器学习编译器，用于编译TensorFlow模型。

**工作流程**：
- 将HLO IR表示的计算图进行与部署平台无关的优化
- 在后端基于硬件架构进行再次优化
- 将优化后的HLO IR转变为更低级的LLVM IR并生成机器码

**特点**：
- 与TensorFlow深度集成
- 支持TPU、GPU、CPU
- 自动算子融合和布局优化

### 8.3 ONNX Runtime

微软推出的跨平台推理引擎，支持多种硬件加速器。

**特点**：
- 编译速度快（ResNet-50仅需15秒）
- 跨框架兼容（PyTorch、TensorFlow、scikit-learn等）
- 支持多种执行提供程序（CUDA、TensorRT、DirectML、OpenVINO等）
- 但性能低于专用编译器（TensorRT、TVM）

### 8.4 Triton

OpenAI推出的Python-like GPU编程语言，核心优势：
- 分块编程模型（Tile-based）
- 自动内存合并和共享内存管理
- 与PyTorch深度集成
- FlashAttention-2使用Triton在A100上达到72%理论算力利用率

**Triton与TileIR的关系**：Triton的分块编程模型可以直接编译到CUDA Tile IR虚拟指令集，获得高性能和跨版本兼容性。

## 总结

量化与编译优化是提升深度学习推理性能的两大核心技术支柱：

**量化技术**通过降低精度实现内存和计算效率的飞跃：
- INT8量化可减少75%模型体积，提升2-4倍推理速度
- FP8量化在H100上可实现2-3倍加速，精度损失极小
- 量化感知训练（QAT）是保持精度的最佳方案

**编译优化技术**通过静态分析和代码生成突破性能瓶颈：
- **TensorRT**：NVIDIA GPU上的性能之王，LLM推理首选
- **TVM**：跨硬件的端到端编译器，自动调度实现极致优化
- **MLIR**：通用编译基础设施，构建多层次优化管道
- **TileIR**：GPU Tile编程的新一代IR，实现跨架构兼容

对于实际部署，建议采用分层优化策略：算法层（FlashAttention）→ 框架层（torch.compile）→ 量化层（INT8/FP8）→ 编译器层（TensorRT/TVM）。大多数场景下，**torch.compile + 量化**的组合已能达到70-80%的最优性能，只有在特定硬件上追求极致性能时才需要深入编译器底层。
