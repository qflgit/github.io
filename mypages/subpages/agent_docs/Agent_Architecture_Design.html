1. Agent 基础概念

1.1 什么是 Agent

Agent（智能体） 是一个能够感知环境、做出决策并执行动作以实现特定目标的自主系统。与传统软件不同，Agent 具备以下核心特征：

1.2 Agent vs. 传统 LLM 应用

传统 LLM 应用：  输入 -> LLM -> 输出（一次性对话）
Agent 系统：    感知 -> 思考 -> 行动 -> 观察 -> ... -> 目标达成（循环迭代）

关键区别：Agent 引入了行动循环（Action Loop），使模型能够：

  • 调用外部工具（API、数据库、搜索引擎）

  • 执行代码或操作环境

  • 维护跨会话的状态和记忆

  • 进行多步规划和错误恢复

2.2 感知层 (Perception Layer)

负责接收和解析外部输入，将其转换为 Agent 可理解的内部表示。

输入类型：

  • 文本输入：用户自然语言、结构化指令

  • 多模态输入：图像、音频、视频（通过多模态模型处理）

  • 结构化数据：JSON、数据库查询结果、API 响应

  • 环境状态：系统指标、文件系统变化、网络事件

处理流程：

xxxxxxxxxx
class PerceptionModule:
    def process(self, raw_input) -> Observation:
        # 1. 输入验证与清洗
        cleaned = self.sanitize(raw_input)
        # 2. 意图识别
        intent = self.intent_classifier.classify(cleaned)
        # 3. 实体提取
        entities = self.ner.extract(cleaned)
        # 4. 上下文关联
        context = self.context_manager.resolve(entities)
        return Observation(intent, entities, context)

3. 经典架构模式

3.1 ReAct (Reasoning + Acting)

论文：ReAct: Synergizing Reasoning and Acting in Language Models (Yao et al., 2022)

核心思想：将推理（Thought）和行动（Action）交织进行，形成思考-行动-观察的循环。

架构流程：

xxxxxxxxxx
用户查询
    |
[思考] 我需要搜索相关信息
    |
[行动] 调用 search_tool(query="...")
    |
[观察] 获得搜索结果
    |
[思考] 根据结果，我需要进一步分析...
    |
[行动] 调用 analyze_tool(data=...)
    |
...（循环直到完成）
    |
[最终答案]

Prompt 模板：

xxxxxxxxxx
你正在解决问题：{question}


你可以使用以下工具：
{tool_descriptions}


请按以下格式思考：
思考：你的推理过程
行动：工具名称[参数]
观察：工具返回结果


（重复思考-行动-观察直到获得答案）


最终答案：你的最终回答

适用场景：问答、信息检索、简单任务执行

3.2 Plan-and-Solve

核心思想：先制定完整计划，再按步骤执行，减少中间推理的冗余。

架构对比：

xxxxxxxxxx
ReAct:     思考 -> 行动 -> 观察 -> 思考 -> 行动 -> ...（细粒度交替）
Plan-and-Solve:  计划[1,2,3] -> 执行1 -> 执行2 -> 执行3 -> 总结（粗粒度分离）

优势：

  • 减少 Token 消耗（避免重复思考）

  • 计划可缓存和复用

  • 便于并行执行独立步骤

劣势：

  • 对动态环境适应性差

  • 计划错误可能导致级联失败

3.3 Reflexion

论文：Reflexion: Self-Reflective Agents (Shinn et al., 2023)

核心思想：引入自我反思机制，Agent 能评估自己的失败并从错误中学习。

架构组件：

xxxxxxxxxx
+-------------+     +-------------+     +-------------+
|   执行器     |---->|   评估器     |---->|   记忆系统   |
|  (Actor)    |     |  (Evaluator)|     |  (Memory)   |
+-------------+     +-------------+     +-------------+
                           |
                           v
                    +-------------+
                    |   自我反思   |
                    |(Self-Reflection)|
                    +-------------+

工作流程：

  1. 执行：Agent 尝试完成任务

  2. 评估：外部评估器或 LLM 判断结果质量

  3. 反思：生成失败原因分析和改进建议

  4. 存储：将反思结果存入长期记忆

  5. 重试：基于反思结果重新尝试

3.4 LLM Compiler

核心思想：将任务编译为有向无环图（DAG），识别并行性，优化执行效率。

架构特点：

xxxxxxxxxx
原始任务："比较A公司和B公司的财务数据，并生成图表"


编译后 DAG：

+---------+   +---------+
|分析A数据 |   |分析B数据 |  <- 并行执行
+----+----+   +----+----+

     +-------------+

优势：最大化并行度，减少总执行时间

4.2 记忆存储实现

4.2.1 短期记忆（上下文窗口）

直接利用 LLM 的上下文窗口（通常 4K-128K tokens）。

管理策略：

  • 滑动窗口：保留最近 N 轮对话

  • 摘要压缩：对历史对话进行 LLM 摘要，减少 token 占用

  • 关键信息提取：只保留实体、意图、决策等关键信息

4.2.2 长期记忆（向量数据库）

使用向量数据库存储和检索语义记忆。

架构流程：

xxxxxxxxxx
class VectorMemory:
    def __init__(self, embedding_model, vector_store):
        self.embedder = embedding_model
        self.store = vector_store


    def store(self, text, metadata=None):
        embedding = self.embedder.encode(text)
        self.store.add(embedding, text, metadata)


    def retrieve(self, query, top_k=5):
        query_embedding = self.embedder.encode(query)
        return self.store.search(query_embedding, top_k)

5.2 规划算法详解

5.2.1 ReAct 规划

xxxxxxxxxx
class ReActAgent:
    def run(self, task, max_iterations=10):
        thoughts = []
        actions = []
        observations = []


        for i in range(max_iterations):
            # 构建 prompt
            prompt = self._build_prompt(task, thoughts, actions, observations)


            # LLM 生成下一步
            response = self.llm.generate(prompt)


            # 解析 Thought 和 Action
            thought, action = self._parse(response)


            if action.is_final():
                return action.answer


            # 执行工具
            observation = self.tools.execute(action)


            thoughts.append(thought)
            actions.append(action)
            observations.append(observation)


        raise MaxIterationsExceeded()

5.2.2 Tree-of-Thought (ToT)

论文：Tree of Thoughts: Deliberate Problem Solving with Large Language Models (Yao et al., 2023)

核心思想：维护一个推理树，在每个节点评估多个候选思路，选择最有希望的深入探索。

xxxxxxxxxx
                    [问题]
                      |
        +-------------+-------------+
        |             |             |
        v             v             v
    [思路 A]      [思路 B]      [思路 C]
    (评分: 0.3)   (评分: 0.8)   (评分: 0.5)
                      |
              +-------+-------+
              |               |
              v               v
          [思路 B1]        [思路 B2]
          (评分: 0.9)      (评分: 0.7)
              |
              v
          [最终答案]

算法流程：

  1. 分解：将问题分解为多个思考步骤

  2. 生成：每个步骤生成 K 个候选思路

  3. 评估：使用 LLM 或启发式规则评估每个候选

  4. 搜索：使用 BFS/DFS 或束搜索探索最有希望的节点

  5. 回溯：当路径失败时回退并尝试其他分支

5.2.3 LLM PDDL 规划

将自然语言任务转换为 PDDL（Planning Domain Definition Language）格式，使用经典规划器求解。

优势：

  • 计划可验证（形式化正确性）

  • 可处理复杂约束

  • 与符号 AI 结合

6.3 CrewAI 架构

核心概念：

  • Agent：具有角色、目标、背景故事和工具的个体

  • Task：分配给 Agent 的具体任务

  • Crew：协作完成任务的多 Agent 团队

  • Process：任务执行流程（顺序、层级）

架构示例：

xxxxxxxxxx
from crewai import Agent, Task, Crew, Process


researcher = Agent(
    role='研究员',
    goal='收集最新AI趋势',
    tools=[search_tool, web_scraper]
)


writer = Agent(
    role='作家',
    goal='撰写技术博客',
    tools=[doc_tool]
)


task1 = Task(description='研究2026年AI趋势', agent=researcher)
task2 = Task(description='撰写博客文章', agent=writer, context=[task1])


crew = Crew(agents=[researcher, writer], tasks=[task1, task2], process=Process.sequential)
result = crew.kickoff()

7.3 关键工程实践

7.3.1 可观测性

必须监控的指标：

  • 延迟：端到端响应时间、LLM 调用延迟、工具执行时间

  • 质量：任务成功率、步骤正确率、用户满意度

  • 成本：Token 消耗、API 调用次数、基础设施成本

  • 安全：权限拒绝次数、异常行为检测

工具链：

  • LangSmith：LangChain 生态的调试和监控平台

  • Langfuse：开源 LLM 工程平台

  • Phoenix：Arize AI 的开源可观测性工具

  • Weights & Biases：实验跟踪和模型管理

xxxxxxxxxx
class ResilientToolExecutor:
    def execute(self, tool, params):
        for attempt in range(3):
            try:
                return tool.run(params)
            except (TimeoutError, RateLimitError):
                if attempt < 2:
                    time.sleep(2 ** attempt)  # 指数退避
                    continue
                raise
            except ToolError:
                # 降级策略
                if tool.has_fallback:
                    return tool.fallback.run(params)
                raise

7.3.3 安全设计

多层防护：

  1. 输入层：Prompt 注入检测、内容过滤（PII、毒性）

  2. 权限层：RBAC（基于角色的访问控制）、最小权限原则

  3. 执行层：沙箱隔离（gVisor、Firecracker）、资源限制

  4. 输出层：事实核查、幻觉检测、输出审查
