5.1 主要注册中心对比

重要提示：没有任何单一注册中心索引所有服务器。部署前应在至少两个来源交叉验证服务器状态，并检查是否被归档。

5.2 服务器卡片 (MCP Server Cards)

2026 年路线图包含 MCP Server Cards 标准，通过 .well-known URL 暴露服务器元数据，使浏览器、爬虫和注册中心无需连接即可发现能力。这将大幅提升服务器发现效率。

6. 网关与聚合工具

6.1 为什么需要网关

Perplexity CTO Denis Yarats 在 Ask 2026 大会上指出两个规模化问题：

  1. MCP 工具描述消耗 40-50% 的上下文窗口

  2. 跨多服务的认证流程难以管理

MCP Gateway 模式应运而生，作为聚合层集中认证、惰性加载工具描述，将上下文使用降至 5-15%。

7. 最佳实践

7.1 服务器配置

  • 使用工作区级配置 (.kiro/settings/mcp.json) 存放项目特定服务器

  • 使用用户级配置 (~/.kiro/settings/mcp.json) 存放全局/跨工作区服务器

  • 工作区配置优先于用户配置（同名冲突时）

  • 始终指定精确版本或使用 @latest 保证稳定性

7.2 安装与设置

  • Python 服务器使用 uvx 命令（需安装 uv 包管理器）

  • uvx 服务器无需单独安装，自动下载

  • 配置后立即测试服务器，不要等问题出现

7.3 安全与自动审批

  • autoApprove 谨慎使用，仅对可信低风险工具启用

  • 添加前审查工具能力

  • 定期审计自动审批工具的安全影响

  • 考虑环境特定的自动审批设置

7.4 性能优化

  • 禁用未使用的服务器以改善启动时间

  • 自动审批使用具体工具名而非通配符

  • 监控服务器资源使用并适时调整

  • 限制同时加载的服务器数量（建议 4-5 个）

7.6 开发工作流
