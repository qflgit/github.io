1. MCP 协议概述

MCP（Model Context Protocol，模型上下文协议）由 Anthropic 于 2024 年末推出，旨在标准化 AI 应用与外部工具、数据源之间的交互方式。截至 2026 年，MCP 已获得广泛采用，被 Claude Desktop、Cursor、Windsurf 等主流 AI 开发工具原生支持。

为什么需要 MCP？

在 MCP 出现之前，每个 AI 工具都有自己的集成方式：

  • Claude 插件：一套 API

  • ChatGPT 插件：另一套 API

  • LangChain 工具：又一套抽象

  • AutoGen 工具：再一套定义

结果：同一个工具需要为 N 个 AI 平台写 N 份集成代码，开发者疲于维护多套适配器。

MCP 通过标准化协议解决了这个问题：一次实现，所有支持 MCP 的 AI 应用均可使用。

MCP 标准协议
     ↓
Claude / Cursor / Windsurf / 其他支持 MCP 的 AI 应用
     ↕ MCP
MCP Server（数据库/文件/API等）

2. 核心概念

MCP 协议定义了三种核心资源类型：

2.1 Tools（工具）

允许服务器公开可执行的函数，供客户端调用，并由 LLM 使用以完成特定操作。例如：查询数据库、发送邮件、调用 API。

xxxxxxxxxx
{
    "name": "send_email",
    "description": "发送邮件",
    "inputSchema": {
        "type": "object",
        "properties": {
            "to": {"type": "string"},
            "subject": {"type": "string"},
            "body": {"type": "string"}
        }
    }
}

2.2 Resources（资源）

表示服务器向客户端提供的各类只读数据，如文件、数据库记录、图片或日志等，用于为 LLM 提供上下文信息。

xxxxxxxxxx
{
    "name": "database://users",
    "description": "用户数据表",
    "mimeType": "application/json"
}

2.3 Prompts（提示词）

由服务器定义的可重用指令或模板，用户可以通过选择提示词来引导或标准化与 LLM 的交互过程。

xxxxxxxxxx
{
    "name": "code_review",
    "description": "代码审查提示词",
    "arguments": [
        {"name": "language", "required": True}
    ]
}

4. 从零构建 MCP Server

4.1 最简 MCP Server（Python）

这是使用官方 SDK 的基础写法，适合理解 MCP 协议底层机制。

文件：server.py

xxxxxxxxxx
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent


# 初始化服务器
server = Server("my-first-server")


@server.list_tools()
async def list_tools():
    # 列出服务器提供的所有工具
    return [
        Tool(
            name="get_weather",
            description="获取指定城市的天气信息",
            inputSchema={
                "type": "object",
                "properties": {
                    "city": {
                        "type": "string",
                        "description": "城市名称，如：北京、上海"
                    }
                },
                "required": ["city"]
            }
        )
    ]


@server.call_tool()
async def call_tool(name: str, arguments: dict):
    # 处理工具调用请求
    if name == "get_weather":
        city = arguments["city"]
        # 实际项目中这里调用天气 API
        return [TextContent(
            type="text",
            text=f"城市 {city} 今天晴，温度 25°C，空气质量优"
        )]
    raise ValueError(f"未知工具: {name}")


async def main():
    # 启动服务器
    async with stdio_server() as (read_stream, write_stream):
        await server.run(read_stream, write_stream)


if __name__ == "__main__":
    import asyncio
    asyncio.run(main())

运行服务器：

xxxxxxxxxx
uv run server.py

关键要点：

  1. 使用 @app.tool() 装饰器将函数注册为 MCP 工具

  3. 函数参数自动映射为工具参数（通过类型注解和 docstring）

  4. 函数的文档字符串用于描述工具功能和参数

  5. 使用 stdio 作为传输协议（最常用）

5. 传输模式详解

MCP 支持两种主要传输模式：

5.1 stdio 模式

特点：

  • 通过标准输入输出流通信

  • 由客户端（如 Claude Desktop）启动 Server 进程

  • 适合本地开发和单机部署

  • 无需网络端口，安全性高

配置示例（Claude Desktop）：

xxxxxxxxxx
{
    "mcpServers": {
        "my-analytics": {
            "command": "uv",
            "args": [
                "--directory",
                "/path/to/my-mcp-server",
                "run",
                "analytics_server.py"
            ]
        }
    }
}

配置示例（Cursor）：

xxxxxxxxxx
{
    "mcpServers": {
        "my-analytics": {
            "command": "python",
            "args": ["/path/to/my-mcp-server/analytics_server.py"]
        }
    }
}

5.2 SSE 模式

特点：

  • 通过 HTTP SSE（Server-Sent Events）通信

  • Server 独立运行，客户端通过网络连接

  • 适合远程部署和多客户端共享

  • 需要处理网络稳定性和认证问题

启动 SSE Server：

xxxxxxxxxx
# 修改最后一行
if __name__ == "__main__":
    app.run(transport='sse', port=8080)

配置示例（SSE 客户端）：

xxxxxxxxxx
{
    "mcpServers": {
        "remote-analytics": {
            "type": "sse",
            "url": "http://localhost:8080/sse"
        }
    }
}

模式对比：

建议： 开发阶段使用 SSE 模式便于调试，生产环境使用 stdio 模式或 SSE + 认证。

import pytest
import asyncio
from mcp.client.stdio import stdio_client
from mcp import ClientSession, StdioServerParameters


@pytest.fixture
async def mcp_session():
    # 创建 MCP 客户端会话
    server_params = StdioServerParameters(
        command="uv",
        args=["run", "weather_server.py"]
    )


    async with stdio_client(server_params) as (read_stream, write_stream):
        async with ClientSession(read_stream, write_stream) as session:
            await session.initialize()
            yield session


@pytest.mark.asyncio
async def test_list_tools(mcp_session):
    # 测试工具列表
    tools = await mcp_session.list_tools()
    tool_names = [tool.name for tool in tools]

7. 进阶：LangChain + MCP 集成

将 MCP Server 与 LangChain 结合，可以构建更强大的企业级 Agent。

xxxxxxxxxx

                              ↓
                        RAG 知识库

7.2 核心代码

xxxxxxxxxx
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_openai import ChatOpenAI
from langchain_mcp import MCPToolkit
from langchain_core.prompts import ChatPromptTemplate


# 1. 初始化 MCP Toolkit
toolkit = MCPToolkit(
    server_command=["uv", "run", "analytics_server.py"]
)


# 2. 获取 MCP 工具
tools = toolkit.get_tools()


# 3. 创建 Agent
llm = ChatOpenAI(model="gpt-4o", temperature=0)
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一位企业数据分析助手，可以查询销售数据、员工绩效、生成周报。"),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}")
])


agent = create_tool_calling_agent(llm, tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)


# 4. 执行任务
result = agent_executor.invoke({
    "input": "查询销售额前3的产品，并生成一份简要分析报告"
})
print(result["output"])

        # 3. 错误处理
        return [TextContent(type="text", text=f"查询失败: {str(e)}")]
